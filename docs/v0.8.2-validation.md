# v0.8.2 구현·검증 기록

기준: v0.8.1 `81b4e49`, 최종 패치 계획 `97e6421`. v0.9는 작업하지 않았다.

## 구현과 원인

- 보상 레이아웃 충돌을 재현했다. 600px에서 기존 카드 폭은 262/262/542px이고 세 번째 카드 offsetTop이 다른 줄이었다. `style.css`의 flex:1과 뒤에 로드되는 모바일 wrap 규칙이 함께 적용된 것이 원인이다.
- 보상 관련 규칙을 `combat.css` 한 곳으로 모았다. 모든 카드는 flex:0 0 210px, 한 줄 nowrap, 양끝 padding 8px, x proximity 스냅과 컨테이너 가로 스크롤을 사용한다. 760px 이하에서 왼쪽 정렬하고, 충분한 데스크톱 폭에서는 중앙 정렬한다. 설명이 길면 같은 줄 카드 높이가 함께 늘어난다.
- 일반 휠의 세로 입력은 넘치는 보상 영역에서만 가로로 적용하며 끝에 도달하면 문서 스크롤을 막지 않는다. Shift+휠/가로 트랙패드는 브라우저 기본 동작을 유지한다. 좁은 화면의 포커스/스냅 충돌을 확인해 포커스 카드가 영역 안에 들어오도록 보정했다. 건너뛰기는 스크롤 밖에 있다.
- 선택된 살아 있는 적에게 청록색 반투명 발밑 타원, 부드러운 glow와 위로 사라지는 선택광을 CSS로 구현했다. 기존 fighter-base 기준으로 배치하고 스프라이트 높이 변수의 90%를 사용한다. 베이스/선택광 z-index 1, 이미지 2, 정보 3으로 분리한다. 키보드 포커스는 금색 점선이다.
- 링과 수직광은 기본/움직임 줄이기 모두 고정식이다. 빠른 깜빡임이나 추가 확대는 없다. 이미지나 참고 에셋을 복사하지 않았다. 기존 공격·피격 이동은 그대로다.
- 첫 턴 배너, 첫 턴 안내 토글과 action을 제거했다. 기존 guide 필드는 저장/JSON 호환을 위해 허용하지만 화면 로직에서는 읽지 않는다. 도움말과 도입 화면의 직접 도움말 버튼은 유지한다. 새로운 상시 안내 문구는 추가하지 않았다.
- `crest-ui.ts`가 기존 crestReady 결과와 AbilityState를 읽어 문장명·능력명, 현재 진행, 사용 버튼을 표시한다. 사용 완료/봉인/남은 조건/사용 가능을 구분하고 disabled 이유를 aria-describedby로 연결한다. 능력 버튼 접근성 이름은 전체 능력명이다.
- 매튜 연계 0/4, 미나 개화 0/6, 정석 비축 0/3, 리키 희망 0/3, 나리 빛 0/6을 방어 바로 위 절대 위치 칩으로 표시한다. 값 0에서도 유지한다. 태일/한솔의 카드 횟수는 진행란이며, 소라는 빈 칩이 없다. 재생·반격·공격 강화·치명 피해 보호는 일반 효과 영역으로 이동했다.
- 모바일 상단 높이는 공통 변수 --topbar-content=48px로 조정했다. 전체 높이는 여기에 env(safe-area-inset-top)을 더하고, 상단 padding도 그 safe area를 사용한다. 네 메뉴는 44px 열/44px 터치, 간격 2~4px이며 데스크톱 콘텐츠 높이는 60px다. 스크롤 여백과 관련 offset은 기존 --topbar-size를 사용한다.
- 엔진, 대상 판정, 카드/보상 결과, 저장 schema v2와 영구 강화는 변경하지 않았다. 새 의존성이나 래스터 에셋은 없다.

## 확인된 결과

- 테스트 110개 통과. 기존 판정 비교 608개 시나리오에서 결과·난수·진화 일치.
- 프로덕션 빌드와 Pages 검사 통과. 로컬 HTTP 215 URL 정상.
- 600px에서 카드 3개 모두 폭 210px/같은 offsetTop, rail clientWidth 545/scrollWidth 682, 문서 overflow 없음, 상단 높이 48px 확인.
- 600px 및 320px 일반 글자에서 통합 DOM 검사 전체 통과. 8명 자원 변화 전후 전장/스프라이트 상대 좌표가 고정되고 실제 카드 획득 및 건너뛰기가 유지됐다.

실제 Galaxy S23+, 노치 iPhone 및 iOS Safari는 연결되어 있지 않다. CSS viewport 검사는 데스크톱 Chromium에서 수행하며 실제 기기 safe area 값이나 물리적 터치/트랙패드의 감각을 대신하지 않는다. 200% 검사는 문서 rem 확대이며 OS 글자 확대/페이지 줌과 다르다.


## 반응형·접근성 최종 확인

- 320px / 문서 글자 200%에서 보상 1~3장·긴 설명, 8명 HUD, 중첩 위치/고정 geometry, 선택광 레이어, 메뉴 10회 소리 전환을 포함한 전체 검사 통과. 확대 시 사용 버튼의 intrinsic 폭/높이와 방어 행의 em 높이를 사용해 글자 및 상태 칩 겹침을 보완했다.
- 긴 설명 fixture는 카드 ID를 실제 데이터 키에서 선택하며, fixture 렌더 성공 표시를 검증해 이전 화면을 잘못 검사하지 않도록 했다.
- 350/360/384/390/600px에서 카드 3개 모두 같은 offsetTop, 폭 210px, 높이 328px. 레일 전체 scrollWidth 682px, 문서 가로 넘침 없음. 상단 높이 48px, 네 버튼 모두 44×44px/동일한 y=1.5px.
- 1280px에서 레일 clientWidth와 scrollWidth가 모두 820px로 불필요한 가로 스크롤이 없다. 카드 3개는 동일 폭/높이의 중앙 정렬. 상단 높이는 기존 60px, 네 메뉴 터치 높이는 44px다.
- 모바일 가로 방향의 coarse pointer + 높이 500px 이하에서도 같은 compact 상단바 규칙을 사용한다. 해당 기기 판정과 실제 노치 값은 코드 확인이며 실기기 측정은 아니다.
