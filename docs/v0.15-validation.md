# v0.15.0 · 선택적 계정과 클라우드 저장

검증일: 2026-11-06. Windows / Node 24 / Codex 앱 내 브라우저. 네이티브 COMPUTER-USE와 외부 브라우저 자동화는 사용하지 않았다. 상태: 구현 및 Vercel/Pages 배포 완료.

## 구현 범위

- 사용자 추가 요청을 우선해 이메일 OTP 대신 **아이디 + 비밀번호, 이메일 인증 없음**으로 구현했다. 비밀번호 처리는 Supabase Auth에 맡겼다.
- 설정의 계정 화면에서 가입·로그인·로그아웃, 8슬롯과 공용 기록 비교, 전체 올리기·불러오기, 충돌 선택, 수동 재시도, 별도 확인을 거친 클라우드 삭제를 제공한다.
- schema 3 / JSON formatVersion 2 유지. 첫 연결과 페이지 재시작 때 저장 방향을 명시적으로 선택한다. 선택 후에만 해당 페이지에서 자동 동기화한다.
- Supabase 테이블 RLS, 본인 전용 읽기와 RPC 쓰기, 서버 revision CAS, 중복 요청 UUID, 계정 전환·응답 역전 방지. 삭제 표식으로 오래된 기기의 기록 부활을 막는다.
- JSON 가져오기·로컬 초기화·다른 탭 변경은 동기화를 중단한다. 게임 규칙·밸런스·콘텐츠·아트는 바꾸지 않았다.
- [CLOUD_SAVE.md](../CLOUD_SAVE.md)에 가입 운영, 공개값 설정, migration, 복구·계정 삭제, 요금·제약 및 공식 자료를 기록했다.

- 이전 v0.14 정적 빌드에 합성 8슬롯을 유지하고 신나리 귀환 결과를 만든 뒤 v0.15로 교체했다. 업데이트 확인에서 새 버전을 찾았다.
- **업데이트 적용의 15초 내 자동 새로고침은 이번에도 성공하지 않았다.** 이는 v0.14 때 관찰한 제한이다. 해당 origin의 게임 탭을 닫고 다시 열자 v0.15가 활성화됐고, 8슬롯·신나리 결과·설정·기존 테스트 Auth 세션이 유지됐다. 자동 적용 성공으로 기록하지 않는다.
- 앱 정적 서버와 테스트 API를 모두 중단하고 v0.15 새로고침 성공. 설정을 41→42%로 바꾼 뒤 다시 새로고침해 42%와 8슬롯 보존을 확인했다. 계정 lazy 모듈도 캐시에서 로드되고 개인 클라우드 조회만 연결 대기/실패 처리된다.
- 코드/단위 검사에서 외부·Authorization·POST·no-store 요청의 캐시 제외를 확인했다. 워커 캐시 복구와 계정 토큰/게임 localStorage를 분리했다.

## 남은 제한

이메일 복구·셀프 계정 삭제·슬롯별 병합은 없다. 계정 삭제와 비밀번호 복구는 운영자 절차다. PWA 자동 적용 지연과 물리 모바일 검증 범위는 위에 명시했다. 재접속 시 수동 비교를 요구하므로 앱을 닫은 뒤 보이지 않게 저장하는 기능은 없다. 공개 URL/가입과 무료 프로젝트 일시 중지·사용량 제한은 운영 문서에 설명했다.
