# v0.14 · Vercel 배포 이전 검증

2026-11-06 · 제품 0.14.0 · 저장 schema 3 유지. 전투 규칙·카드·밸런스 변경 없음.

## 구현

- `config/deployment.mjs`의 Pages `/file-island-echoes/`, Vercel `/` 두 대상을 Vite/PWA/검사에서 공유한다. 빌드 대상 불일치는 실패시킨다.
- manifest id/start_url/scope, worker URL, HTML·그림·폰트·오디오 URL과 해시 메타데이터를 대상별로 생성한다. Vercel 정적 배포 설정과 크롤러 응답 헤더를 추가했다.
- Pages는 기존 캐시 이름을 유지하고 루트는 root 접두사를 사용한다. 업데이트/복구가 다른 대상의 캐시를 지우지 않는다.
- 데이터 관리에 원본 내보내기 → 대상 미리보기/확인과 별도 홈 화면 앱 안내를 넣었다. 기존 8명 슬롯과 공유 도감·설정 형식은 유지한다.
- Private 저장소에 접근할 수 없는 버그 신고자는 다운로드로 전달할 수 있다. 자동 전송하지 않는다.
- [배포 안내](../DEPLOYMENT.md)에 현재 Hobby·Git 작성자·GitHub 접근 권한·production 보호 조건과 실제 공개 범위의 차이를 정리했다.

## Codex 앱 내 브라우저

- 서로 다른 로컬 origin을 사용했다. Pages 3030, 루트 3031/3032. 사용자의 공개 사이트 기록은 수정하지 않았다.
- 합성 8명 체크포인트와 도감·클리어·설정을 Pages 실제 데이터 관리에서 JSON으로 내보내고, 루트 실제 파일 선택/미리보기/확인으로 불러왔다. 대상 재내보내기와 원본의 payload 전체가 정확히 일치했다. 원본 슬롯 비교도 `unchanged:true, count:8`이었다.
- 루트에서 가져온 신나리 전투를 실제 카드 입력으로 승리까지 진행했다. 카드 비용·드로우·적 행동과 보상 3장을 확인했다.
- 루트 음악 28파일 OGG/MP3가 캐시에서 실제 AudioContext 디코딩 PASS. 루트 scope `/` 및 root shell/music/runtime 이름을 진단 UI에서 확인했다.
- 두 서버를 중단하고 양쪽 새로고침 → 이어하기 성공. Pages 전투와 루트 보상 상태 및 이미 본 그림을 복원했고, 음악 재생 상태와 출력 미터를 확인했다. 서버만 중단했으므로 navigator.onLine 표시는 여전히 온라인일 수 있다.
- 루트 업데이트는 전투 중 적용 불가, 보상에서 적용 가능. 여러 진단/게임 탭이 열린 첫 시도는 15초 안에 적용되지 않았다. 중복 게임 탭을 닫은 뒤 새 worker가 활성화되고 수동 새로고침에서 새 JS 해시를 확인했다. HP 56/64, 에너지 5, 유대 2, 부담 0과 보상 3장이 유지됐다. 최초 시도에서 즉시 자동 새로고침이 성공했다고 주장하지 않는다.
- 320×740에서 이전 안내를 펼쳤다. 실제 innerWidth 320, 문서 scrollWidth 305, summary 높이 50.39px로 가로 넘침 없이 스크롤 가능했다. 스크린샷은 로컬 `test-results/v0.14-migration-mobile.jpg`.

## 배포

Vercel `jmhan/file-island-echoes` 프로젝트를 생성하고 GitHub `jimyeong-han/file-island-echoes` 연결 성공을 확인했다. 첫 연결의 Login Connection 오류는 재시도로 해소됐다. 사용자는 이미 GitHub 계정을 연결해 둔 상태였다.

실제 production 배포 주소와 최종 외부 검증은 아래에 추가한다. 저장소는 공개 상태이며 Private 전환이나 배포 인증 정책 변경을 수행하지 않았다.

## 제한

물리 Android/iOS 설치 앱, OS 저장 공간 퇴거, 실제 스피커 출력은 이번에 측정하지 않았다. 여러 백그라운드 탭이 열린 상태의 업데이트 자동 새로고침 지연은 위 관찰 범위로 남긴다. 계정 동기화(v0.15)는 구현하지 않았다.
