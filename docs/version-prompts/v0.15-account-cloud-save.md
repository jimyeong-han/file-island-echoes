# v0.15 — 계정별 클라우드 저장

- 상태: 구현·로컬 검증 완료 (운영 배포 확인 대기)
- 유형: 기능 버전
- 선행 버전: v0.14 및 이전 patch
- 제품 버전: `0.15.0`

## 다른 세션에 전달할 프롬프트

```text
File Island Echoes에 선택적 계정 로그인과 계정별 클라우드 저장·불러오기를 추가해줘. AGENTS.md, 버전 문서, v0.7 JSON, v0.10 다중 슬롯 저장·충돌 처리, v0.14 배포, PWA 오프라인 동작과 Git 상태를 먼저 확인한다. v0.14 및 선행 patch를 완료하고 기존 사용자 변경사항을 보존한다.

1. 기존 로컬 플레이와 JSON 백업을 그대로 유지하고, 로그인한 사용자는 8명 캐릭터 슬롯·공용 도감·해금·설정을 계정에 저장해 다른 기기에서 복원할 수 있게 한다. Vercel과 연결 가능한 Supabase Auth + Postgres를 기본 설계로 사용한다. 이메일 로그인 또는 사용 가능한 소셜 로그인을 채택하되 실제 제공자 설정, redirect URL, 이메일 확인·복구 및 서비스 요금/제약을 공식 문서와 프로젝트 환경에서 확인한다. 비밀번호를 직접 저장·구현하지 않는다.

2. Supabase 프로젝트와 인증 제공자 설정, 환경변수, SQL migration, 로컬·Vercel 설정 및 운영 절차를 문서화한다. 공개 클라이언트 키만 브라우저에 전달하고 service-role 키나 비밀 인증정보는 절대 포함하지 않는다. 저장 테이블은 인증 사용자 ID별로 분리하고 RLS를 활성화하여 본인만 읽고 쓰게 한다. 미인증 사용자와 다른 계정의 접근 거부를 실제 정책 테스트로 검증한다. 사용자 가입 개방 여부는 지인 대상 사용을 고려해 설정 가능하게 하고, 계정 기능이 게임 URL 자체의 접근 제한은 아니라는 점을 설명한다.

3. 첫 로그인 시 로컬 데이터와 클라우드 데이터의 존재 여부, 캐릭터별 진행·시각을 비교해 보여 주고 사용자가 올리기 또는 불러오기를 명시적으로 선택하게 한다. 양쪽 모두 기록이 있으면 자동 덮어쓰지 않는다. 전체 프로필과 8개 슬롯의 범위가 명확해야 한다. 기존 JSON export/import와 v1/v2/v3 이전을 유지하며, 교체 전에 로컬 JSON 백업 경로를 제공한다.

4. 오프라인에서는 로컬 자동 저장을 계속한다. 온라인 복귀 후 로그인 상태에서 저장을 재시도하고 동기화 중·완료·실패를 설정 또는 저장 화면에 간결하게 표시한다. revision/서버 측 원자적 비교로 다른 기기나 탭에서 변경된 기록을 감지하고 자동 덮어쓰지 않는다. 충돌 시 양쪽의 캐릭터별 요약과 시간 및 전체 프로필 교체 범위를 보여주고 사용자가 선택한다. 시간만으로 최신 판정하지 않는다. 중복 요청·전송 실패·서버 응답 역전·로그아웃 및 계정 전환에서 다른 계정의 데이터가 섞이지 않게 한다. 백그라운드 비밀 저장 및 서비스 워커 캐시에 인증 토큰이나 개인 저장 payload를 넣지 않는다.

5. 게임 내 계정 화면에 로그인·로그아웃·동기화 상태·수동 재시도·클라우드 불러오기를 제공한다. 로그아웃과 기기 로컬 삭제, 클라우드 기록 삭제의 범위를 명확하게 구분하고 삭제에는 별도 확인을 요구한다. 계정 삭제 기능을 제공한다면 인증 서비스와 DB 데이터 정리까지 다루고, 제공하지 않는다면 운영자가 처리하는 절차를 문서화한다. 불필요한 개인정보와 분석 SDK를 수집하지 않는다. 전투 중 상시 배너를 넣지 않는다.

6. 두 계정 간 격리 및 RLS, 첫 로그인 선택, 슬롯 8개 왕복, JSON 백업, 네트워크 단절·재접속·동기화 충돌, 두 기기/탭 동시 수정, 중복 요청, 만료 세션, 로그아웃·다른 계정 로그인, 실패 복구, 저장 schema 호환과 PWA 업데이트를 검증한다. 테스트는 별도 테스트 프로젝트/계정 및 격리된 데이터로 실행하고 실제 사용자 기록을 지우지 않는다. npm test, npm run build, Pages/Vercel 및 PWA 검사와 모바일 브라우저 경로를 확인한다.

실제 Supabase 프로젝트·인증 설정 권한이 없다면 코드와 migration, 재현 가능한 로컬 테스트 및 사용자가 수행할 설정 절차까지 완성하고 실제 계정 생성·운영 동기화가 완료됐다고 주장하지 않는다. docs/v0.15-validation.md에 환경·검증 결과와 남은 설정을 기록한다. 버전과 관련 문서를 갱신하고 필요할 때만 명시적으로 저장 schema를 올린다.
```

## 완료 조건

- 계정별로 캐릭터 슬롯과 공용 기록을 저장하고 다른 기기에서 안전하게 불러온다.
- 비로그인·오프라인 플레이와 JSON 백업이 유지되고 충돌 시 자동 덮어쓰지 않는다.
- 계정 간 접근이 차단되고 배포·인증 설정과 실제 검증 범위가 문서화된다.

## 구현 기록 · 2026-11-06

- 사용자 추가 지시에 따라 이메일 확인 없는 아이디·비밀번호 가입으로 구현했다. Supabase Auth, 본인 RLS + revision CAS RPC, 8슬롯 비교/전체 교체, 오프라인 로컬 보존, 재시도·충돌·중복·계정 전환을 처리한다. 저장 schema 3 유지.
- 운영 SQL과 가입 설정, Vercel/Pages 공개 환경변수를 적용했다. 로컬 두 계정 실제 정책 12그룹, 자동 테스트 236개, 두 배포 빌드와 앱 내 브라우저 검증을 완료했다.
