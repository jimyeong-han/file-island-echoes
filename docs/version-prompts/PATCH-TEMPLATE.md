# v0.x.y — 버그 수정명

- 상태: 초안
- 유형: 버그 수정
- 선행 버전: v0.x 또는 v0.x.(y-1)
- 제품 버전: `0.x.y`
- 작성일: YYYY-MM-DD

## 증상

사용자가 관찰하는 문제를 적는다. 오류 메시지, 발생 화면과 영향을 구체적으로 기록한다.

## 재현 절차

1. 시작 상태
2. 수행한 입력
3. 문제가 나타나는 지점

## 기대 동작

정상이라면 관찰되어야 하는 결과를 적는다.

## 현재 동작

실제로 관찰되는 결과를 적는다. 원인이 확인되지 않았다면 증상과 추측을 구분한다.

## 다른 세션에 전달할 프롬프트

```text
현재 저장소의 File Island Echoes v0.x에서 발생한 버그를 v0.x.y patch로 수정해줘.

먼저 AGENTS.md, docs/version-prompts/README.md, 기반 기능 버전과 직전 patch 프롬프트, 현재 코드·테스트·Git 상태를 확인한다. 기존 사용자 변경사항을 보존한다.

증상:
[사용자가 관찰한 문제]

재현 절차:
[정확한 단계]

기대 동작:
[정상 결과]

현재 동작:
[실제 결과]

먼저 동일한 증상을 재현하고 증거를 바탕으로 원인을 격리한다. 가설을 한 번에 여러 개 수정하지 않는다. 원인을 설명할 수 있는 가장 작은 범위로 수정하고 관련 없는 기능이나 콘텐츠를 추가하지 않는다.

전투 UI를 수정할 때는 사용자가 명시적으로 요청하지 않은 상시 설명 문구, 반복 튜토리얼 배너, 설명 카드나 홍보성 문구를 임의로 덧붙이지 않는다. 조작 방법은 기존 도움말에 통합하고 전투 화면에는 플레이 판단, 상태와 조작에 필요한 정보만 유지한다.

회귀 검사를 추가하거나 기존 검사를 강화해 수정 전에는 문제를 검출하고 수정 후에는 통과하게 한다. 저장, 전투, 모바일 UI, 오디오 또는 Pages 경로처럼 영향을 받을 수 있는 인접 기능도 위험에 비례해 확인한다.

자동 테스트, 프로덕션 빌드, Pages 경로 검사와 실제 재현 경로의 브라우저 검증을 수행한다. package.json과 사용자에게 표시되는 버전을 0.x.y로 맞춘다. 수정 내용, 원인, 검증 결과와 남은 제한을 기록하고 이 patch 문서 상태를 완료로 갱신한다.

다음 기능 버전은 이 patch가 완료된 뒤에 진행한다. 추가 버그가 발견되면 v0.x.(y+1) 문서를 만들고 같은 순서로 처리한다.
```

## 완료 조건

- 기록된 재현 절차에서 증상이 더 이상 발생하지 않는다.
- 수정 원인을 검출하는 회귀 검사가 통과한다.
- 기반 기능 버전의 완료 조건이 계속 충족된다.
- 제품 버전과 문서 상태가 `0.x.y`에 맞게 갱신된다.

## 구현 기록

완료 세션이 원인, 변경 파일, 테스트·브라우저 검증 결과와 구현 기준을 기록한다.
