# v0.9 — 모바일 PWA

- 상태: 구현 완료 · v0.9.1 패치 예정 (실기기 검증 제외)
- 유형: 기능 버전
- 선행 버전: v0.8.2
- 제품 버전: `0.9.0`
- 작성일: 2026-09-11

## 목표

File Island Echoes를 모바일 브라우저에서 홈 화면에 설치해 독립 앱처럼 실행할 수 있는 PWA로 만든다. GitHub Pages의 하위 경로에서도 설치·업데이트·오프라인 재실행이 안정적으로 동작하고, 진행 중인 게임을 예고 없이 새로고침하지 않도록 한다.

## 다른 세션에 전달할 프롬프트

```text
현재 저장소의 File Island Echoes v0.8.2를 v0.9 모바일 PWA로 업데이트해줘.

먼저 AGENTS.md, docs/version-prompts/README.md, docs/version-prompts/v0.9-mobile-pwa.md, package.json, vite.config.ts, index.html, GitHub Pages 배포 설정, 정적 에셋 구조, 저장·오디오 초기화 코드와 Git 상태를 확인한다. v0.8.2가 완료된 구현을 기준으로 작업하고 기존 사용자 변경사항을 보존한다.

핵심 목표는 Android와 iOS에서 웹사이트를 홈 화면에 추가해 standalone 앱처럼 실행하는 것이다. 단순히 manifest 파일만 추가하고 완료 처리하지 말고, 설치 가능성, GitHub Pages의 `/file-island-echoes/` base path, service worker scope, 오프라인 재실행, 업데이트 전환과 모바일 실제 사용 흐름을 함께 구현·검증한다.

1. Web App Manifest와 앱 메타데이터

유효한 web app manifest를 추가하고 빌드 결과의 HTML에서 올바르게 연결한다.

manifest 기본값:
- name: `디지몬: 우리들의 모험`
- short_name: 모바일 홈 화면에서 잘리지 않는 짧은 이름을 정해 사용
- description: 과장되지 않은 한 문장 게임 설명
- lang: `ko`
- display: `standalone`
- orientation: `any` 또는 생략해 회전을 잠그지 않고, 현재 주 사용 환경인 세로 화면을 우선 최적화하되 가로 화면도 정상 동작
- theme_color와 background_color: 현재 짙은 남청색 UI와 일치
- start_url, scope와 id: GitHub Pages의 `/file-island-echoes/` 배포 경로 안에서 동작하도록 base-aware한 값 사용

현재 Vite 설정은 `base: '/file-island-echoes/'`다. manifest, 아이콘, service worker와 앱 내부 에셋 URL에 사이트 루트 `/`를 잘못 가리키는 절대 경로를 남기지 않는다. 로컬 개발과 Pages 배포 양쪽에서 `import.meta.env.BASE_URL`, Vite의 public asset 처리 또는 선택한 PWA 플러그인의 base 처리를 일관되게 사용한다.

필수 아이콘을 제공한다.
- 192×192 일반 아이콘
- 512×512 일반 아이콘
- 192×192 및 512×512 maskable 용도 또는 purpose가 올바른 동등 구성
- Apple touch icon에 적합한 PNG
- 브라우저 favicon 유지

아이콘은 기존 게임 로고와 디지바이스풍 시각 언어를 바탕으로 작은 크기에서도 식별되는 단순한 구성으로 만든다. 공식 로고나 원작 이미지를 복사하지 않는다. maskable 아이콘은 중요한 도형과 글자를 중앙 안전 영역 안에 두고 Android 원형·둥근 사각형 마스크에서 잘리지 않게 한다. SVG 하나만 manifest의 유일한 아이콘으로 두지 말고 실제 PNG 크기를 제공한다.

index.html에 manifest link, theme color, Apple touch icon과 필요한 iOS standalone 메타데이터를 추가한다. viewport의 safe area 처리가 필요하면 `viewport-fit=cover`를 적용하되, 기존 상단바와 하단 콘텐츠가 노치·홈 인디케이터에 가려지지 않도록 현재 safe-area CSS와 함께 검증한다.

2. Service worker와 캐시 전략

Vite 환경에 맞는 검증된 PWA 방식(vite-plugin-pwa/Workbox 또는 규모에 맞는 직접 구현)을 선택한다. 직접 구현한다면 install, activate, fetch, 캐시 버전 정리, navigation fallback과 오류 처리를 자동 테스트 가능한 작은 모듈로 유지한다. 외부 CDN이나 원격 런타임에 새로 의존하지 않는다.

캐시 원칙:
- 앱 shell, JS/CSS, manifest, 필수 UI 아이콘과 핵심 폰트는 새 빌드에 맞춰 precache
- 화면 이동과 새로고침에 필요한 navigation 요청은 Pages base 경로의 index.html로 안전하게 fallback
- 해시가 붙은 빌드 에셋은 cache-first로 재사용
- 캐릭터·배경 이미지와 오디오는 runtime cache를 사용할 수 있으나 모든 대형 파일을 첫 설치 때 무조건 내려받지 않음
- 한 번 정상적으로 불러온 탐험·전투에 필요한 에셋은 이후 오프라인 재실행에서 사용할 수 있게 함
- 범위를 벗어난 URL, GitHub, 분석·제3자 요청은 캐시하거나 가로채지 않음
- opaque response와 실패 응답을 무조건 캐시하지 않음
- 캐시 이름에 앱/빌드 버전을 반영하고 activate 때 이 앱의 오래된 캐시만 정리
- 저장 JSON, localStorage와 사용자 진행 데이터는 HTTP cache에 넣거나 지우지 않음

대형 이미지와 mp3/ogg가 많은 프로젝트이므로 precache 크기와 브라우저 저장 공간을 측정한다. 최초 방문을 과도하게 느리게 만들거나 모바일 데이터에서 전체 오디오 라이브러리를 내려받지 않는다. 오프라인 중 아직 캐시되지 않은 선택형 에셋은 게임 전체가 흰 화면으로 중단되지 않도록 기존 이미지 fallback과 오디오 무음 fallback을 유지한다.

service worker는 프로덕션 빌드에서만 또는 개발 환경을 오염시키지 않는 방식으로 등록한다. 등록 URL과 scope가 `/file-island-echoes/` 밖으로 벗어나거나 `/file-island-echoes/file-island-echoes/`처럼 중복되지 않는지 확인한다. 등록 실패가 게임 시작을 막지 않게 하고, 개발 중 남은 service worker 때문에 최신 코드 확인이 꼬이지 않도록 개발 안내도 남긴다.

3. 설치 경험

지원 브라우저에서는 설치 진입점을 설정 또는 정보 화면 안에 제공한다. 전투 상단바에 새 상시 버튼이나 긴 안내 배너를 추가해 높이를 늘리지 않는다.

Android/Chromium:
- `beforeinstallprompt`를 보관하고 사용자가 `앱으로 설치`를 눌렀을 때만 prompt 실행
- 이벤트가 없거나 이미 설치된 경우 사용할 수 없는 버튼을 무의미하게 노출하지 않음
- `appinstalled`와 `display-mode: standalone`을 기준으로 설치 상태 갱신
- 브라우저가 설치를 허용하지 않는 상황을 설치 성공으로 표현하지 않음

iOS Safari:
- iOS에서 지원되지 않는 가짜 설치 버튼을 만들지 않음
- 설치하지 않은 iOS Safari 사용자에게만 설정/도움말에서 `공유 → 홈 화면에 추가`라는 짧은 수동 절차 제공
- 이미 standalone으로 실행 중이면 안내 숨김

설치 권유는 첫 화면을 가리는 강제 팝업이나 매 방문 반복 배너로 만들지 않는다. 설치하지 않아도 기존 브라우저 게임을 동일하게 플레이할 수 있어야 한다. 설치 상태 감지는 플랫폼 문자열 하나에만 의존하지 말고 capability와 display mode를 우선한다.

4. 업데이트 경험

새 service worker가 준비돼도 진행 중 전투나 탐험을 예고 없이 reload하지 않는다.

- 새 버전이 대기 중이면 설정 또는 작은 비차단 알림으로 `새 버전 사용 가능`과 적용 버튼 제공
- 사용자가 적용을 선택하면 현재 자동 저장을 마친 뒤 새 worker를 활성화하고 한 번만 reload
- 전투 중이라면 즉시 재시작을 강요하지 않고 안전한 시점에 적용할 수 있게 함
- 같은 worker 상태 변화로 reload loop가 생기지 않도록 제어
- 오프라인에서는 업데이트 버튼을 성공한 것처럼 처리하지 않음
- 업데이트 후에도 v0.8.2 저장 데이터와 설정을 그대로 읽음

캐시된 구버전 HTML과 새 JS 청크가 섞여 chunk load 오류가 나는 경우를 고려해 recovery 흐름을 만든다. 단, 오류가 날 때마다 캐시 전체와 저장 데이터를 무차별 삭제하지 않는다. PWA 캐시 초기화가 필요하다면 설정의 진단/복구 기능으로 HTTP cache만 안전하게 정리하고 사용자 진행 데이터는 보존한다.

5. 모바일 standalone UI

설치 실행 시 브라우저 주소창이 없는 화면에서도 기존 반응형 UI가 자연스럽게 차지하도록 한다.

- v0.8.2의 모바일 48px 상단바와 최소 44×44px 터치 영역 유지
- `env(safe-area-inset-top/right/bottom/left)`를 상단 고정바, 팝업, 하단 버튼과 가로 모드에 필요한 곳에 일관되게 반영
- 100vh 고정 때문에 주소창 변화나 standalone 모드에서 하단이 잘리지 않도록 필요하면 `dvh`와 안전한 fallback 사용
- Galaxy S23+ 세로/가로, Android Chrome 설치 실행과 일반 탭 실행에서 레이아웃 비교
- iPhone Safari 탭, 홈 화면 standalone과 노치 기기에서 상단·하단 가림 확인
- 화면 꺼짐·앱 전환·복귀 뒤 오디오와 저장 상태가 기존 정책대로 복원
- standalone 여부만으로 게임 규칙, 저장 슬롯이나 콘텐츠를 다르게 만들지 않음

온라인/오프라인 상태를 꼭 표시해야 한다면 설정 또는 연결 오류 맥락에 짧게 제공한다. 전투 화면에 상시 `오프라인 가능`, 설치 홍보 또는 조작 설명을 추가하지 않는다.

6. 저장과 개인정보

PWA 설치는 기존 localStorage 저장 형식과 v0.7 JSON 내보내기/불러오기를 그대로 사용한다. 설치 앱과 같은 origin의 브라우저 탭이 저장을 공유할 수 있다는 점, 앱 제거나 브라우저 데이터 삭제 시 로컬 기록이 사라질 수 있다는 점을 도움말에 짧게 설명하고 중요한 기록은 JSON으로 내보낼 수 있게 한다.

service worker, manifest와 설치 기능을 위해 분석 SDK, 푸시 알림, 백그라운드 동기화, 계정, 위치 또는 불필요한 권한을 추가하지 않는다. 외부 네트워크 전송도 추가하지 않는다.
```

## 완료 조건

- GitHub Pages 하위 경로에서 manifest와 service worker가 올바른 URL과 scope로 제공된다.
- Android에서 홈 화면 설치 후 standalone으로 실행할 수 있고, iOS에는 정확한 수동 설치 안내가 제공된다.
- 첫 온라인 실행 뒤 핵심 게임 화면을 오프라인에서 다시 열 수 있으며 미캐시 에셋 실패가 전체 게임을 중단하지 않는다.
- 새 버전이 준비돼도 진행 중 게임을 예고 없이 새로고침하지 않고 사용자가 안전하게 적용한다.
- 모바일 상단바, 터치 영역, 노치·홈 인디케이터 safe area와 세로·가로 레이아웃이 유지된다.
- 기존 저장·JSON 내보내기·오디오 동작이 유지되고 캐시 정리가 사용자 진행 데이터를 삭제하지 않는다.
- 설치 기능 때문에 추적, 푸시 알림, 계정이나 불필요한 권한이 추가되지 않는다.
- 자동 검사, production preview, 오프라인·업데이트 시나리오와 가능한 기기 검증 결과가 문서화된다.

## 구현 기록

2026-09-11 v0.9.0 구현. 직접 구현 worker와 Vite 후처리를 사용하며 의존성 추가 없음. manifest/PNG/Pages scope, 원자적 shell 캐시, 파일 내용별 runtime 캐시, 설정의 설치·대기 업데이트·전투 차단·저장 후 적용·HTTP 캐시 복구를 구현했다. 사용자 후속 요청으로 터치 피드백 7종만 사전 다운로드/캐시하며 음악은 지연 로드한다. 테스트 125개, 빌드·Pages·HTTP223 URL 및 브라우저 오프라인/업데이트/저장/모바일 검증 통과. 상세 구현 기준은 [v0.9 검증 기록](../v0.9-validation.md)과 [PWA.md](../../PWA.md). Android/iOS 실기기 설치, 노치, 스피커 출력은 미검증이다. v0.9.1과 v0.10은 실행하지 않았다.

구현 세션이 선택한 PWA 방식과 의존성, manifest·아이콘, Pages base와 worker scope, precache/runtime cache 정책과 용량, 설치·업데이트 UX, 오프라인 fallback, 모바일 safe area, 저장 호환성, 자동·브라우저·실기기 검증 및 구현 기준 커밋을 기록한다.
