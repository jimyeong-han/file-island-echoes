# v0.14 — Vercel 배포 이전

- 상태: 예정
- 유형: 기능 버전
- 선행 버전: v0.13 및 이전 patch
- 제품 버전: `0.14.0`

## 다른 세션에 전달할 프롬프트

```text
File Island Echoes를 개인 GitHub 비공개 저장소에서도 Vercel에 배포할 수 있도록 이전해줘. AGENTS.md, 버전 문서, Git 상태, vite.config.ts, scripts/build-pwa.mjs, PWA worker·manifest·오디오 캐시와 GitHub Pages 설정을 먼저 살펴보고, v0.13 및 선행 patch를 순서대로 완료한다. 다른 세션의 작업과 사용자 변경을 보존한다.

현재 Vite와 PWA 빌드에는 GitHub Pages 하위 경로 `/file-island-echoes/`가 고정돼 있다. Vercel의 루트 경로와 기존 Pages 하위 경로를 환경별로 명시적으로 설정해 Vite base, 정적 파일, manifest id/start_url/scope, worker 등록·캐시·업데이트·음악 선캐시가 일관되게 작동하도록 정리한다. 절대 경로를 무작정 치환하지 말고 빌드 스크립트·테스트·버그 신고 링크·오디오·아이콘까지 조사한다. 기존 Pages 호환을 유지하며 환경별 명령과 Vercel의 build/output 설정을 문서화한다. 비밀키를 저장소나 브라우저 코드에 넣지 않는다.

Vercel 새 도메인은 기존 Pages와 origin이 달라 브라우저 저장과 PWA 설치가 자동 이동하지 않는다. 기존 사이트의 데이터 관리에서 JSON 내보내기 → Vercel 사이트에서 불러오기 절차를 안내하고, 8명 슬롯·도감·설정과 기존 파일 버전을 보존한다. 구 사이트 또는 사용자의 기록을 자동 삭제하거나 덮어쓰지 않는다. 기존 PWA는 별도 설치임을 안내한다.

개인 Private GitHub 저장소 연결과 Vercel Hobby의 현재 제한, Git 작성자 자동 배포 조건 및 GitHub 접근 권한을 공식 문서로 확인해 README에 적는다. Private 저장소가 배포 URL의 접근 제한을 의미하지 않는다는 점을 설명한다. 지인 접근 제한 방법과 요금제 조건은 확인된 사실만 기록하고 사용자 승인 없이 인증 정책을 강제하지 않는다.

로컬 production 환경에서 Vercel 루트와 Pages 하위 경로 각각 빌드·미리보기, asset 경로, manifest와 service worker scope, 새로고침·오프라인·음악·업데이트·JSON 이전을 검증한다. npm test, npm run build, 관련 Pages/PWA 검사도 실행한다. 실제 Vercel 계정·저장소 권한이 제공되면 연결과 배포를 진행하고, 사용할 수 없다면 배포 가능한 설정 및 구체적인 연결 절차를 남기며 실제 배포·Private 전환이 완료됐다고 주장하지 않는다. 실제 배포본 URL과 검증 여부는 docs/v0.14-validation.md에 기록한다. 저장 schema는 변경이 없다면 유지하고 제품 버전과 프롬프트 상태를 갱신한다. 이후 v0.15 계정 저장을 진행한다.
```

## 완료 조건

- Vercel 루트와 기존 Pages 경로에서 게임·PWA가 동작한다.
- 기존 저장을 JSON으로 안전하게 이전할 수 있고 접근 공개 여부가 명확하다.
- 실제 배포 여부와 검증 결과가 구분되어 기록된다.
