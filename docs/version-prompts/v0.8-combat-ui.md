# v0.8 — 전투 UI와 카드 애니메이션

- 상태: 예정
- 유형: 기능 버전
- 선행 버전: v0.7.1
- 제품 버전: `0.8.0`
- 작성일: 2026-09-11

## 목표

카드를 실제 손에 든 카드처럼 보이도록 재설계하고, 카드 배분·사용과 적 행동에 짧고 명확한 애니메이션을 추가한다. 모바일 전투 중 내 디지몬의 남은 체력을 계속 확인할 수 있게 하며, 전투 기록의 시간 순서를 바로잡고 상단 컨트롤을 한 줄 고정형으로 정리한다.

## 다른 세션에 전달할 프롬프트

```text
현재 저장소의 File Island Echoes를 v0.8로 업데이트해 카드 외형, 전투 피드백 애니메이션, 체력 정보, 전투 기록과 상단바를 개선해줘.

먼저 AGENTS.md, docs/version-prompts/README.md, v0.7 및 존재하는 모든 v0.7.x patch 문서, README.md, VALIDATION.md, 현재 카드·전투·애니메이션·헤더 구현과 Git 상태를 확인한다. v0.7.1까지 완료되지 않았다면 버전 순서에 따라 먼저 완료한다. 기존 사용자 변경사항을 보존한다.

현재 전투 규칙, 카드 비용과 효과, 덱 구성, 적 AI, 진화 조건, 저장 데이터의 의미는 바꾸지 않는다. 이번 버전은 정보 구조와 시각적 피드백을 개선하는 UI 업데이트다. 애니메이션 때문에 게임 판정 시점이 달라지거나 같은 행동이 두 번 실행되지 않게 한다.

1. 실제 카드처럼 보이는 카드 디자인

현재 손패와 카드 선택 UI를 납작한 버튼 목록이 아니라 실제 카드 한 장처럼 인식되는 디자인으로 재구성한다. 특정 상용 카드 게임이나 Slay the Spire의 프레임·아이콘·색 배치를 복제하지 않고 File Island Echoes만의 디지바이스, 데이터 회로와 문장 모티프를 사용한다.

각 카드에는 다음 정보가 한눈에 구분되어야 한다.
- 좌상단 또는 상단 모서리의 에너지 비용
- 카드 이름
- 카드 타입 또는 역할
- 일러스트/기술 이미지 영역
- 효과 설명과 수치
- 연계, 소멸, 비축 등 핵심 키워드
- 캐릭터 전용·진화 단계 등 실제로 필요한 구분

외형 요구사항:
- 세로로 긴 실제 카드 비율과 둥근 모서리
- 종이 카드의 테두리, 얇은 내부 프레임과 가벼운 재질감
- 공격·방어·기술·특수 카드의 색 차이는 유지하되 색만으로 구분하지 않음
- 카드 뒷면은 문장·디지바이스·데이터 회로를 조합한 프로젝트 고유의 대칭 무늬
- 카드 이름과 비용은 손패 크기에서도 즉시 읽힘
- 효과 설명은 작은 모바일 화면에서도 충분한 대비와 행간을 유지
- 사용 가능, 비용 부족, 선택됨, 대상 선택 중과 비활성 상태가 명확히 다름
- 마우스 hover뿐 아니라 키보드 focus-visible과 터치 선택 상태 제공

모바일 손패는 카드가 화면 밖으로 사라지지 않도록 겹침, 부채꼴, 가로 스크롤 또는 확대 선택 중 현재 구조에 가장 안정적인 방식을 선택한다. 선택한 카드는 위로 살짝 올라오고 설명을 읽을 수 있어야 한다. 인접 카드의 터치 영역이 겹쳐 엉뚱한 카드가 선택되지 않게 하며 최소 터치 영역을 확보한다.

카드 프레임과 뒷면은 CSS/SVG 등 가벼운 에셋을 우선하고, 공식 카드 프레임이나 원작 이미지를 추출해 사용하지 않는다. 장식 때문에 초기 로딩과 전투 렌더링이 눈에 띄게 느려지지 않게 한다.

2. 카드 사용 애니메이션

전투 중 카드를 확정해 사용할 때 선택된 카드의 시각적 복제본을 overlay에 만들고 다음 흐름으로 재생한다.

1) 선택 카드가 손패에서 약간 확대되며 위쪽의 플레이 영역으로 40~72px 정도 떠오른다.
2) 이동 중 카드의 테두리 또는 타입 색이 짧게 빛난다.
3) 플레이 영역에 도달하는 시점에 카드 효과, 피해·방어·상태 아이콘과 기존 효과음을 동기화한다.
4) 효과가 적용된 뒤 카드는 약간 더 위로 이동하면서 자연스럽게 fade out한다.

권장 전체 길이는 약 280~380ms다. 실제 구현과 기존 모션 톤에 맞춰 조절하되 매 카드마다 플레이를 답답하게 기다리게 하지 않는다. 원본 손패 DOM을 직접 날려 레이아웃이 출렁이게 하지 말고 overlay/clone 또는 동등한 방식으로 손패 자리와 스크롤 위치를 안정적으로 유지한다.

애니메이션 중 같은 카드를 두 번 누르거나 다른 입력으로 효과가 중복 적용되지 않게 한다. 카드 효과의 게임 상태는 한 번만 커밋하고 애니메이션 완료 이벤트에만 의존해 판정을 유실하지 않는다. 대상 선택 취소, 전투 종료, 화면 전환과 애니메이션 중 컴포넌트 해제도 안전하게 처리한다.

3. 전투 시작·턴 시작 카드 받기와 뒤집기

전투 시작의 첫 손패와 각 플레이어 턴 시작의 새 손패에 카드 받기 애니메이션을 추가한다.

동작 순서:
1) 덱 위치 또는 정해진 시작점에서 카드 뒷면이 손패 자리로 이동한다.
2) 여러 장은 약 60~100ms 간격으로 순서대로 도착한다.
3) 각 카드가 자리에 도착하면 Y축 3D 회전처럼 보이는 flip을 시작한다.
4) 회전 중간 지점에서 뒷면을 앞면으로 교체하고 자동으로 끝까지 뒤집는다.
5) 마지막 카드가 도착하면 손패 전체가 즉시 조작 가능한 안정 상태가 된다.

뒤집기 전부터 DOM이나 접근성 트리에 카드 정답이 불필요하게 중복 노출되지 않게 한다. 실제 드로우 결과와 난수는 애니메이션 전에 확정하고 모션은 결과를 표현만 해야 한다. 애니메이션 도중 빠르게 누르거나 턴 종료를 연타해 카드가 중복 지급되지 않게 한다.

첫 손패가 5장인 현재 규칙과 턴별 드로우 규칙을 그대로 따른다. 카드 수가 달라지거나 추가 드로우가 발생해도 고정된 5장 전용 코드로 깨지지 않게 구성한다. 탭이 백그라운드로 갔다 돌아오거나 애니메이션이 취소되면 모든 카드를 앞면·조작 가능 상태로 정리한다.

4. 내 디지몬 아래에 현재 체력 표시

전투 화면에서 적의 체력을 적 캐릭터 아래에서 확인하는 것과 같은 방식으로, 내 디지몬 바로 아래에도 현재 체력 정보를 표시한다. 모바일에서 카드와 행동 영역을 보고 있을 때 체력을 확인하려고 문서 맨 위까지 스크롤할 필요가 없어야 한다.

표시 내용:
- 현재 체력 / 최대 체력 숫자
- 남은 비율을 보여 주는 체력 바
- 체력이 감소·회복할 때 짧은 변화 피드백
- 위험 구간의 시각적 경고

적 체력 UI와 같은 시각 언어를 사용하되 누구의 체력인지 혼동되지 않게 파트너 이름 또는 접근 가능한 라벨을 제공한다. `progress`/meter에 준하는 의미와 현재값·최대값을 스크린리더에 전달한다. 색만으로 위험 상태를 표현하지 않는다.

중복된 상단 체력 정보가 있다면 정보 자체는 유지해도 되지만 서로 다른 값이 보이는 이중 상태를 만들지 않는다. 단일 전투 상태에서 파생해 동시에 갱신한다. 피해, 회복, 최대 체력 증가, 진화, 빛의 공명과 패배 직전/직후 값이 정확히 반영되어야 한다.

390×844, 384px 안팎의 갤럭시 S23+ CSS viewport와 320×740에서 실제 전투 스크롤 위치를 확인한다. 내 디지몬과 체력 바가 카드·버튼·전투 기록에 가려지거나 화면 밖으로 잘리지 않게 한다.

5. 턴 종료 후 적 행동 애니메이션

턴 종료를 누른 뒤 적의 예고 행동이 실제로 실행될 때 행동 종류를 알아볼 수 있는 짧은 애니메이션을 추가한다.

- 공격: 적이 플레이어 쪽으로 짧게 전진하거나 타격선/충격 효과를 표시하고 내 디지몬이 짧게 피격 반응
- 다단 공격: 실제 타격 횟수와 맞는 간결한 펄스 또는 연속 타격
- 방어: 적 주변에 방어막이 형성되고 방어 수치가 갱신
- 강화·약화·상태 부여: 해당 상태의 색과 아이콘이 적 또는 대상 쪽으로 이동하거나 나타남
- 회복: 체력 바 증가와 회복 피드백 동기화

적의 의도 표시 → 턴 종료 입력 잠금 → 적 행동 모션 → 수치·상태 결과 확인 → 다음 턴 카드 배분 순서가 명확해야 한다. 전투 기록, 체력 바, 효과음과 화면 효과의 시점을 가능한 한 맞춘다. 여러 적이 있으면 실제 행동 순서대로 재생하되 전체 대기 시간이 과도하게 길어지지 않게 한다.

적 행동 중 턴 종료를 다시 누르거나 카드를 사용할 수 없게 하고, 행동이 끝나면 반드시 다음 턴으로 진행한다. 적 처치, 플레이어 패배, 상태 피해로 인한 중간 사망과 화면 이탈에서도 모션 큐가 멈추거나 다음 턴이 이중 시작되지 않아야 한다.

6. 전투 기록 순서 수정

현재 전투 기록의 번호가 화면에서 역순으로 보이는 문제를 수정한다. 기록은 위에서 아래로 `1 → 2 → 3 → ...`의 발생 순서대로 표시하고, 새 기록은 목록 맨 아래에 추가한다. 번호는 현재 배열 인덱스를 임의로 뒤집은 값이 아니라 실제 발생 순서를 나타내야 한다.

표시를 위해 원본 상태 배열에 `.reverse()`를 직접 적용해 상태 자체를 변형하지 않는다. 역순 표시 코드, CSS의 `column-reverse`, 번호 계산과 자동 스크롤을 함께 점검한다. 기록 영역이 스크롤된다면 새 항목이 추가될 때 사용자가 이미 맨 아래를 보고 있는 경우에만 자연스럽게 최신 항목으로 따라가고, 과거 기록을 읽는 중에는 강제로 위치를 빼앗지 않는다.

턴 번호와 행동 번호가 별도 개념이면 라벨을 명확히 구분한다. 전투 시작부터 종료까지 번호가 중복·누락되지 않고, 다단 공격과 상태 효과가 기존 기록 정책에 맞는 한 사건 또는 여러 사건으로 일관되게 표시되어야 한다.

7. 우측 상단 한 줄 고정 상단바

도감, 소리 켜짐/음소거, 도움말과 설정 컨트롤이 너비를 과도하게 차지하거나 두 줄로 내려가는 문제를 수정한다. 네 컨트롤은 우측 상단의 한 줄 상단바 안에 항상 들어가야 하며, 페이지를 스크롤해도 접근할 수 있도록 sticky 또는 fixed 방식으로 고정한다.

레이아웃 우선순위:
1) 도감·소리·도움말·설정의 기능과 최소 터치 영역 유지
2) 네 버튼을 한 줄에 유지하고 줄바꿈·가로 스크롤 방지
3) 상태 전환 시 각 버튼의 위치와 터치 영역 고정
4) 공간이 부족하면 왼쪽의 `우리들의 모험` 제목을 시각적으로 숨김
5) 그래도 좁으면 버튼 라벨을 아이콘 중심으로 축약하되 접근 가능한 이름과 상태는 유지

제목을 숨길 때 문서의 h1과 앱 이름 자체를 삭제하지 말고 visually-hidden 또는 다른 접근 가능한 방식으로 남긴다. 아이콘만 표시하는 버튼에는 `aria-label`, title/tooltip 등 의미를 제공한다. 소리 버튼은 `소리 켜짐`과 `음소거` 사이에서 폭이 달라져 도감 위치가 움직이지 않게 고정 열 또는 동일 너비를 사용하고 현재 상태를 `aria-pressed` 등으로 전달한다.

상단바는 모바일 safe-area inset, 브라우저 주소창 변화와 200% 확대를 고려한다. 고정 바가 게임 내용, 모달 닫기 버튼이나 카드 대상 선택을 가리지 않도록 본문 상단 여백과 z-index를 정리한다. 320px에서 네 기능을 임의로 숨기거나 더보기 메뉴 깊숙이 넣지 않는다.

8. 모션 접근성과 성능

`prefers-reduced-motion: reduce`에서는 카드 이동·flip·적 돌진을 제거하거나 80ms 이하의 짧은 fade/상태 전환으로 대체한다. 모션을 줄여도 카드 사용, 드로우, 적 행동과 다음 턴 진행은 동일하게 완료되어야 한다.

transform과 opacity 중심으로 애니메이션해 레이아웃 재계산을 줄인다. 무제한 타이머, 애니메이션 DOM 복제본과 event listener가 전투 후 남지 않게 정리한다. 저사양 모바일에서 5장 배분과 다중 적 행동을 확인하고, 효과를 위해 대용량 영상·GIF나 새 런타임 의존성을 추가하지 않는다.

애니메이션은 장식만이 아니라 행동 결과를 설명하므로, 중요한 수치 변화와 상태는 텍스트·아이콘·전투 기록에도 계속 남긴다. 화면 깜빡임, 과도한 흔들림과 강한 섬광을 사용하지 않는다.

9. 검증

카드 UI:
- 모든 카드 타입, 캐릭터 전용 카드와 진화 단계에서 비용·이름·효과·키워드 표시 확인
- 사용 가능/불가, 선택, 대상 지정, hover, 키보드 focus와 터치 상태 확인
```

## 완료 조건

- 카드가 실제 카드처럼 읽히는 독자적인 앞면·뒷면 디자인과 명확한 상태를 가진다.
- 카드 사용 시 위로 이동하고 효과와 동기화된 뒤 fade out한다.
- 전투 및 턴 시작에 카드 뒷면 배분과 자동 flip이 재생된다.
- 내 디지몬 아래에서 현재/최대 체력을 모바일 스크롤 위치와 관계없이 확인할 수 있다.
- 턴 종료 후 적 행동 종류와 결과를 알 수 있는 애니메이션이 재생된다.
- 전투 기록이 위에서 아래로 1, 2, 3의 발생 순서대로 표시된다.
- 도감·소리·도움말·설정이 우측 상단 한 줄 고정 바에 유지되고, 좁으면 제목이 먼저 숨는다.
- reduced-motion, 모바일 터치, 접근성과 기존 전투 판정이 회귀하지 않는다.
