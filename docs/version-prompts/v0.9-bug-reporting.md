# v0.9 — 버그 신고와 수집

- 상태: 예정
- 유형: 기능 버전
- 선행 버전: v0.8.1
- 제품 버전: `0.9.0`
- 작성일: 2026-09-10

## 목표

플레이어가 게임 안에서 재현 가능한 버그 보고서를 작성하고, 포함될 진단 정보를 확인한 뒤 GitHub Issues로 제출하거나 로컬 파일·클립보드로 전달할 수 있게 한다. 정적 사이트에 비밀 토큰이나 자동 추적 기능을 추가하지 않는다.

## 수집 방식 결정

GitHub Pages는 정적 사이트이므로 브라우저 코드에 GitHub 토큰을 넣어 이슈를 자동 생성하면 안 된다. v0.9의 기본 수집함은 `jimyeong-han/file-island-echoes` 저장소의 GitHub Issues다.

- GitHub 계정이 있는 사용자는 미리 채워진 새 이슈 화면에서 내용을 확인한 뒤 직접 제출한다.
- GitHub 계정이 없거나 URL 길이 제한을 넘으면 Markdown 또는 JSON 보고서를 복사·다운로드해 개발자에게 전달할 수 있다.
- 게임은 사용자의 동의 없이 보고서나 진단 데이터를 외부로 전송하지 않는다.

## 다른 세션에 전달할 프롬프트

```text
현재 저장소의 File Island Echoes를 v0.9로 업데이트해 게임 내 버그 신고 작성과 GitHub Issues 기반 수집 흐름을 구현해줘.

먼저 AGENTS.md, docs/version-prompts/README.md, v0.8과 존재하는 모든 v0.8.x patch 문서, 현재 설정·정보·오류 UI, 저장 구조, GitHub 저장소 설정과 Git 상태를 확인한다. v0.8.1까지 완료되지 않았다면 버전 순서에 따라 먼저 완료한다. 기존 사용자 변경사항을 보존한다.

이 프로젝트는 정적 GitHub Pages에서 실행된다. 브라우저 코드, 환경 파일, Actions나 저장소에 개인용 GitHub 토큰을 넣지 않는다. 클라이언트에서 GitHub API로 몰래 이슈를 생성하거나 자동 분석·원격 로깅을 추가하지 않는다. 수집함은 GitHub Issues를 사용하고 최종 제출은 사용자가 GitHub 화면에서 확인해 수행한다.

1. 게임 내 신고 화면

헤더의 정보/설정 영역과 오류 안내에서 접근할 수 있는 “버그 신고” 화면을 추가한다.

입력 필드:
- 제목 또는 한 줄 요약: 필수
- 발생 위치: 타이틀, 선택, 지도, 이벤트, 전투, 진화, 결과, 도감, 설정, 저장/불러오기, 오디오, 기타
- 실제로 일어난 일: 필수
- 기대했던 동작: 필수
- 재현 단계: 필수, 순서가 드러나는 여러 줄 입력
- 발생 빈도: 한 번, 가끔, 항상
- 심각도 체감: 불편, 진행 방해, 진행 불가, 저장 손실 의심
- 추가 설명: 선택

사용자가 입력 중 실수로 화면을 닫아도 같은 세션에서 초안을 복구할 수 있게 한다. 제출 성공으로 오인할 수 있는 표현을 사용하지 않는다. GitHub 이슈 작성 화면을 열었을 뿐이면 “제출 완료”가 아니라 “GitHub에서 최종 제출해 주세요”라고 표시한다.

2. 진단 정보

다음 진단 정보는 사용자가 체크박스로 포함 여부를 선택하고, 전송 또는 복사 전에 전체 내용을 미리 볼 수 있게 한다.

기본 후보:
- 앱 버전과 가능하면 빌드 커밋
- 현재 URL의 pathname만 사용하고 query/hash의 민감한 값은 제외
- 브라우저 종류와 user agent
- 운영체제/플랫폼 정보로 브라우저가 제공하는 일반 값
- viewport와 devicePixelRatio
- 언어와 시간대
- 터치 지원 여부
- 현재 화면, 선택 캐릭터, 챕터와 노드 ID
- 진행 중 전투 여부와 적 ID
- 오디오 context 상태, 사용 포맷, 음소거 여부
- reduced motion 설정
- 저장 schema와 내보내기 format 버전
- 최근 발생한 앱 내부 오류의 정제된 메시지와 코드

포함하지 않을 정보:
- 사용자의 이름, 이메일, GitHub 토큰 또는 인증정보
- localStorage 전체 덤프
- JSON 저장 payload 전체
- 전체 덱·난수 상태·사용자 파일 내용
- 외부 URL의 query token
- 브라우저 히스토리
- 자동 수집한 IP 주소

진행 상태가 재현에 꼭 필요한 경우에도 기본적으로 요약만 포함한다. 전체 저장 JSON은 자동 첨부하지 않는다. 사용자가 v0.7 내보내기 파일을 별도로 전달할 수 있다는 안내만 제공한다.

3. 보고서 생성

입력과 선택한 진단 정보를 일정한 Markdown 보고서로 만든다.

구조:
- 요약
- 발생 위치와 빈도
- 실제 동작
- 기대 동작
- 재현 단계
- 진단 정보
- 추가 설명
- 개인정보를 직접 확인했다는 체크

사용자가 다음 중 하나를 선택할 수 있게 한다.
- GitHub에서 이슈 작성
- Markdown 복사
- `.md` 파일 다운로드
- 구조화된 `.json` 파일 다운로드

Clipboard API가 거절되거나 보안 컨텍스트가 아니면 textarea 선택 또는 파일 다운로드 fallback을 제공한다. 성공과 실패를 aria-live로 알린다.

4. GitHub Issues 연결

저장소에 `.github/ISSUE_TEMPLATE/bug_report.yml`을 추가한다. 게임에서 생성하는 보고서와 같은 항목을 사용하고 다음 안내를 포함한다.
- 비공식 팬 프로젝트임
- 개인정보, 토큰과 민감한 저장 파일을 올리지 말 것
- 중복 이슈 검색 권장
- 재현 단계와 앱 버전 요청

게임의 “GitHub에서 이슈 작성”은 `https://github.com/jimyeong-han/file-island-echoes/issues/new`의 적절한 template, title과 body 파라미터를 사용한다. URL을 만들 때 `URLSearchParams` 등 안전한 인코딩을 사용한다. 보고서가 브라우저 URL 한계를 넘을 가능성이 있으면 본문을 무리하게 잘라 의미를 잃게 하지 말고, Markdown 복사/다운로드 후 빈 이슈 템플릿을 여는 fallback을 안내한다.

새 창이 팝업 차단으로 열리지 않으면 현재 탭 이동 또는 복사 링크를 제공한다. 실제 GitHub 이슈가 생성됐는지 클라이언트가 알 수 없으므로 성공으로 기록하지 않는다.

5. 오류 포착

현재 앱의 예상 가능한 오류 처리와 충돌하지 않는 범위에서 `error`와 `unhandledrejection`을 정제해 최근 오류 한두 건을 메모리에 보관할 수 있다.

- 원본 객체나 전체 사용자 데이터를 직렬화하지 않는다.
- 같은 오류를 무한히 쌓지 않는다.
- 개발 경로, 쿼리 토큰과 긴 스택은 제거하거나 요약한다.
- 오류 수집 자체가 다시 오류를 발생시키지 않아야 한다.
- 새로고침을 넘어 영구 보관할 필요는 없다.
- 자동 전송하지 않는다.

6. 관리와 문서

`BUG_REPORTING.md`에 다음을 기록한다.
- 플레이어 신고 방법
- GitHub Issues가 수집함이라는 점
- 자동 전송과 자동 추적을 하지 않는다는 점
- 포함 가능한 진단 정보
- 저장 파일을 공유할 때의 주의
- 관리자가 재현, 중복, 심각도와 버전을 분류하는 간단한 절차

README와 게임 크레딧/정보 화면에서 버그 신고 위치를 안내한다. 광고, 분석 SDK, 세션 리플레이 또는 제3자 추적 스크립트를 추가하지 않는다.

7. 검증

- 필수 필드 누락과 길이 제한
- 한글, 줄바꿈, 특수문자와 이모지가 Markdown/URL에서 깨지지 않음
- 선택한 진단 정보만 보고서에 포함
- query/hash의 민감 정보가 진단에 들어가지 않음
- localStorage와 저장 payload 전체가 자동 포함되지 않음
- GitHub URL이 올바른 저장소와 템플릿을 가리킴
- 긴 보고서에서 복사/다운로드 fallback 동작
- Clipboard API 거절과 팝업 차단 처리
- 모바일 입력, 키보드 포커스와 aria-live
- 최근 오류 정제와 중복 제한
- 버그 신고 화면을 열고 닫아도 진행 중 탐험과 오디오가 깨지지 않음
- npm test, npm run build, npm run check:pages

자동 검증 중 실제 공개 저장소에 테스트 이슈를 생성하지 않는다. GitHub 이슈 작성 화면의 URL과 미리 채운 내용을 확인하는 지점까지만 테스트한다.

package.json과 사용자에게 표시되는 버전을 0.9.0으로 맞춘다. BUG_REPORTING.md와 VALIDATION.md를 갱신하고 docs/version-prompts/v0.9-bug-reporting.md의 상태를 완료로 바꾼 뒤 구현 기준을 추가한다.
```

## 완료 조건

- 게임 안에서 재현 가능한 보고서를 작성하고 내용을 미리 볼 수 있다.
- 사용자가 선택한 진단 정보만 Markdown과 JSON에 포함된다.
- GitHub Issues 작성, 복사와 로컬 다운로드 경로가 제공된다.
- 토큰, 전체 저장 데이터와 개인정보가 자동 수집·전송되지 않는다.
- 모바일, 접근성, 팝업/클립보드 실패와 기존 게임 흐름이 검증된다.
