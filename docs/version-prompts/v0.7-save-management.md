# v0.7 — 기록 초기화와 JSON 저장 관리

- 상태: 완료
- 유형: 기능 버전
- 선행 버전: v0.6.2
- 제품 버전: `0.7.0`
- 작성일: 2026-09-10

## 목표

사용자가 게임의 모든 기록을 안전하게 초기화하고, 현재 저장 데이터를 로컬 JSON 파일로 내보내거나 다시 불러올 수 있게 한다. 서버 전송 없이 기기 간 수동 백업과 복원을 지원한다.

## 다른 세션에 전달할 프롬프트

```text
현재 저장소의 File Island Echoes를 v0.7로 업데이트해 모든 기록 초기화와 로컬 JSON 저장 내보내기·불러오기 기능을 구현해줘.

먼저 AGENTS.md, docs/version-prompts/README.md, v0.6 문서, 현재 Settings 타입, src/storage.ts, 저장 키·스키마·v1 이관 코드, 이어하기와 도감 UI, Git 상태를 확인한다. v0.6이 완료되지 않았다면 먼저 완료한다. 기존 사용자 변경사항을 보존한다.

설정 또는 별도의 “데이터 관리” 화면에 다음 기능을 추가한다.
- 저장 파일 내보내기
- 저장 파일 불러오기
- 모든 기록 초기화
- 각 기능의 설명, 마지막 내보내기 또는 불러오기 결과 메시지

1. JSON 내보내기

현재 앱이 관리하는 저장 전체를 하나의 JSON 파일로 다운로드한다.

포함 대상:
- 진행 중인 탐험과 전투 체크포인트
- 캐릭터별 챕터 클리어와 엔딩
- 발견한 진화체, 적과 이벤트
- 오디오, 모션, 가이드 등 사용자 설정
- 저장 스키마 버전과 앱 버전

내보내기 envelope 예시:
- app: file-island-echoes
- formatVersion
- appVersion
- exportedAt
- payload

파일명은 `file-island-echoes-save-YYYYMMDD-HHmm.json`처럼 식별 가능하게 한다. JSON은 사람이 열어볼 수 있는 UTF-8 형식으로 만들고 서버에 업로드하지 않는다. Blob URL은 다운로드 후 해제한다.

2. JSON 불러오기

로컬 파일 선택기로 `.json`을 선택하고 내용을 검증한 뒤 복원한다.

필수 검증:
- 최대 파일 크기 제한. 일반 저장 파일에 충분한 범위로 정하고 과도한 파일은 거부
- 올바른 JSON 문법
- app 식별자와 formatVersion
- payload의 객체 형태
- 기존 storage validator와 migration 재사용
- 허용된 enum, 숫자 범위, 배열 길이와 문자열 길이
- prototype pollution에 사용될 수 있는 위험 키를 신뢰하지 않음
- 알 수 없는 필드는 무시하거나 안전하게 거부
- 손상된 run 때문에 archive와 settings까지 모두 잃지 않도록 기존 복구 정책 유지

파일을 읽었다는 이유만으로 즉시 현재 데이터를 덮어쓰지 않는다. 먼저 다음 내용을 미리 보여준다.
- 저장 파일의 앱 버전과 내보낸 날짜
- 진행 중인 캐릭터와 챕터 여부
- 클리어, 도감과 엔딩의 개략적인 수
- 현재 저장이 교체된다는 안내
- 경고 또는 이관 가능 여부

사용자가 명시적으로 “불러와 현재 기록 교체”를 선택한 뒤에만 반영한다. 검증이나 이관에 실패하면 현재 localStorage를 전혀 변경하지 않는다. 성공하면 저장을 한 번에 교체하고 앱 상태를 다시 읽어 타이틀 또는 적절한 안전 화면으로 이동한다.

지원 범위:
- 현재 저장 형식
- 기존 v1 저장과 현재 migration이 지원하는 구버전
- 미래의 더 높은 formatVersion은 무리하게 읽지 않고 지원하지 않는 버전이라고 안내

3. 모든 기록 초기화

앱이 소유한 localStorage 키만 삭제한다. `localStorage.clear()`를 사용해 같은 origin의 다른 데이터를 삭제하지 않는다.

초기화 대상:
- 진행 중인 탐험
- 캐릭터별 클리어와 엔딩
- 도감 및 이벤트 기록
- 오디오와 접근성 설정
- 이 앱이 남긴 구버전 저장 키

초기화 전에 다음을 제공한다.
- 삭제되는 항목의 명확한 목록
- 되돌릴 수 없다는 안내
- 선택적으로 먼저 JSON 백업을 내보내는 버튼
- 1차 버튼 후 별도의 확인 대화상자
- 최종 버튼에는 “모든 기록 초기화”처럼 구체적인 문구 사용

초기화 성공 후 메모리의 save 상태도 새 기본값으로 교체하고 화면을 다시 렌더링한다. 새로고침해야만 반영되는 상태로 두지 않는다. 실패하면 성공했다고 표시하지 않는다.

4. 접근성과 모바일

- 파일 입력은 시각적 버튼과 연결된 label 또는 접근 가능한 제어로 제공
- 확인 dialog는 키보드 포커스 고정과 Escape 취소 지원
- 성공과 오류는 aria-live로 전달
- 오류 메시지에 내부 스택이나 원본 파일 전체를 노출하지 않음
- 320px 모바일에서도 파일 정보와 확인 버튼이 잘리지 않음

5. 저장 호환성

기능 구현에 새 영구 필드가 필요하지 않다면 내부 게임 저장 스키마를 불필요하게 올리지 않는다. 내보내기 파일의 formatVersion은 게임 저장 schema version과 분리할 수 있다. 기존 v2 저장과 v0.5.1의 오디오 설정을 그대로 보존해야 한다.

회귀 및 브라우저 검증:
- 저장이 없는 상태의 내보내기
- 진행 중 탐험, 도감과 설정이 있는 상태의 내보내기
- 내보낸 파일을 같은 브라우저에서 다시 불러와 완전 복원
- 초기화 후 같은 JSON으로 복원
- 구버전 저장 불러오기
- 잘못된 JSON, 다른 app 식별자, 너무 큰 파일, 미래 버전과 손상 payload 거부
- 실패한 불러오기 후 기존 저장이 바뀌지 않음
- 앱 키만 초기화되고 다른 테스트 localStorage 키는 유지
- 초기화 직후 이어하기와 도감이 기본 상태로 갱신
- 음량·음소거·모션 설정 복원
- 모바일 파일 선택과 키보드 dialog 조작
- npm test, npm run build, npm run check:pages

실제 사용자 저장 파일이나 개인정보를 테스트 fixture로 커밋하지 않는다. 합성 fixture만 사용한다. package.json과 사용자에게 표시되는 버전을 0.7.0으로 맞춘다. README와 VALIDATION.md에 저장 파일 형식, 복원 절차, 검증과 호환 범위를 기록한다. docs/version-prompts/v0.7-save-management.md의 상태를 완료로 바꾸고 구현 기준을 추가한다.
```

## 완료 조건

- 현재 기록을 JSON으로 내려받고 같은 상태로 복원할 수 있다.
- 잘못된 파일이 현재 저장을 부분적으로 덮어쓰지 않는다.
- 전체 초기화가 앱 소유 키만 삭제하고 즉시 UI에 반영된다.
- 구버전 저장, 오디오 설정과 모바일 접근성이 검증된다.

## 구현 기록 · 2026-09-11

설정 → 데이터 관리에서 JSON 내보내기, 검증·미리보기 후 교체, 별도 확인 후 전체 초기화를 제공한다. 저장 schema v2는 유지한다. `src/save-files.ts`에 파일 검증·원자적 저장 교체·소유 키 초기화를 분리했다. 구현/검증 상세는 [v0.7 검증 기록](../v0.7-validation.md)을 참고한다. 82개 테스트, 빌드, Pages 검사와 로컬 HTTP 214개 URL 검사 통과. Chromium에서 실제 다운로드 파일의 초기화 후 복원과 새로고침을 확인했다.
