# v0.9.1 — 대상 링·이야기 선택과 오프라인 음악

- 상태: 예정
- 유형: 버그 수정 및 소규모 UX 조정
- 선행 버전: v0.9
- 제품 버전: `0.9.1`
- 작성일: 2026-09-11

## 피드백

- 선택된 적 뒤의 청록색 오오라가 네모난 반투명 판처럼 보이고, 발밑 타원 링에서 솟아오르지 않은 별도 도형처럼 분리돼 있다. 링도 실제 발·몸통의 접지점보다 아래 또는 위에 떠 보여 상대 디지몬이 바닥을 밟고 있다는 느낌이 나지 않는다.
- 이야기 이벤트의 선택지에 체력·유대·부담·진화 에너지·카드 보상 등이 미리 표시돼, 이야기의 맥락보다 수치상 정답을 먼저 고르게 된다.
- v0.9 PWA는 음악을 지연 로드하므로 설치 후 오프라인에서 아직 재생하지 않은 배경음악이 빠질 수 있다. 현재 음악 24개 파일은 MP3·OGG를 합쳐 13,266,249바이트이므로 PWA 준비 과정에서 모두 받아 둔다.

## 첨부 이미지 사용 범위

- 첨부 이미지는 쉘몬 뒤에 네모난 청록색 영역이 보이고 타원 링이 발과 떨어져 보이는 **현재 오류 상태**를 확인하는 용도로만 사용한다.
- 이미지의 캐릭터·배경·체력·행동 예고·글꼴·구도는 새 에셋이나 UI 디자인 참고 대상이 아니다. 이미지를 저장소에 복사하거나 게임 에셋으로 사용하지 않는다.
- 목표 표현은 v0.8.2 기획에 기록된 참고 방향처럼, 상대 디지몬이 바닥에 눌린 타원형 선택광을 직접 밟고 있고 그 타원에서 오오라가 자연스럽게 위로 올라오는 모습이다.

1. 네모난 대상 오오라 제거

현재 `.target-field`가 적 스프라이트 높이의 약 90%까지 올라오는 `linear-gradient`와 좌우 mask를 사용해, 첨부 화면의 쉘몬 뒤에 모서리가 느껴지는 청록색 직사각형 판을 만든다. `.fighter-base::after`의 타원 링과 이 수직 영역이 별개의 도형처럼 보여 부자연스럽다.

다음 기준으로 다시 만든다.
- 타원과 무관하게 수직으로 솟는 직사각형·기둥·사각 mask 표현은 제거
- 타원 바깥으로 네모난 경계나 직선형 좌우 끝이 전혀 보이지 않음
- 선택광의 중심, glow와 외곽선이 모두 같은 타원 중심과 원근을 공유
- 바닥에 눌린 넓고 낮은 시안·청록 타원이며, 높이는 너비보다 충분히 얇아 원근감이 느껴짐
- 타원 내부는 중앙에서 가장 은은하고 가장자리로 자연스럽게 사라지는 radial/elliptical gradient
- 외곽선은 선명한 한 줄이 아니라 가까운 내부광과 부드러운 바깥 glow가 연결된 형태
- 오오라는 **바닥 타원 내부에서 시작해 위로 솟는 하나의 연속된 빛**이어야 하며 타원과 떨어진 별도 배경판으로 보이지 않음
- 오오라 하단의 폭과 중심은 타원의 안쪽 면에 정확히 맞고, 위로 갈수록 폭·불투명도·광량이 부드럽게 줄어듦
- 오오라 좌우는 타원의 곡률을 따라 안쪽으로 휘거나 feather되어 직선 모서리와 사각형 실루엣이 생기지 않음
- 오오라 상단은 캐릭터 높이의 약 70~100% 범위에서 완전히 투명해지고 평평한 수평 끝이 보이지 않음
- 결과적으로 `바닥 타원 → 타원에서 올라오는 오오라 → 그 안에 서 있는 디지몬`이 하나의 선택 필드로 읽혀야 함
- 어두운 배경에서도 선택 여부는 분명하지만 캐릭터 몸 전체를 청록색으로 덮거나 상태 UI보다 밝게 타지 않음

기존 `.target-field`, `.fighter-base::before/::after`와 stacking context를 먼저 정리한다. 같은 효과를 여러 요소에 중복해서 그리지 말고 가능한 한 하나의 ground indicator 컴포넌트와 소수의 pseudo-element로 구성한다. 타원과 상승 오오라가 같은 좌표계·중심·폭 변수를 공유하게 한다. 단순히 opacity만 낮춰 네모 모양을 숨기지 말고 네모를 만드는 geometry 자체를 타원 기반의 feathered gradient로 바꾼다.

2. 실제 접지점에 링 배치

링의 수직 기준은 fighter 컨테이너의 임의 bottom이나 체력 UI가 아니라 **렌더된 디지몬의 발·다리·배 아랫부분이 바닥에 닿는 시각적 접지점**이다. 상대 디지몬이 원 위에 떠 있거나 원 앞에 서 있는 것이 아니라 원 영역을 밟는 것처럼 보여야 한다.

배치 기준:
- 타원의 중심선 또는 뒤쪽 절반이 발·발톱·배의 가장 낮은 접지 부분과 겹침
- 캐릭터 스프라이트는 타원의 뒤쪽 면보다 앞에 보이고, 타원의 앞쪽 호와 glow는 발 앞에서 자연스럽게 보여 입체감을 형성
- 상승 오오라는 타원의 뒤쪽/내부 면에서 시작해 스프라이트 뒤로 올라가며, 발 앞쪽 호보다 앞에 덮이지 않음
- 기존 검은 ground shadow가 있다면 선택 링과 같은 중심·접지점을 공유하도록 통합하거나 정렬
- 링을 추가해 fighter, battlefield, 이름·체력과 전투 UI 전체 높이가 변하지 않음
- 링의 크기는 적 스프라이트의 실제 보이는 몸 폭에 비례하고 작은 적·넓은 적·보스에서 과도하게 남거나 몸 안에 묻히지 않음

에셋의 투명 여백 때문에 CSS 이미지 박스의 bottom이 실제 발 위치와 다를 수 있다. 하나의 고정 `bottom` 값으로 우연히 쉘몬만 맞추지 말고, 현재 적 에셋들의 투명 여백을 점검한다. 필요하면 적 ID/형태별로 데이터 또는 CSS custom property인 `--enemy-ground-offset`, `--enemy-ring-width` 같은 최소한의 보정값을 정의한다. 보정값은 접지점과 폭에만 사용하고 캐릭터마다 무관한 임의 픽셀을 흩뿌리지 않는다.

최소한 다음 체형을 비교한다.
- 아구몬처럼 두 발로 서는 작은 체형
- 쉘몬처럼 넓고 낮으며 배·여러 다리가 지면에 가까운 체형
- 메라몬처럼 사람형에 가까운 체형
- 데블몬처럼 키가 큰 체형
- 보스와 투명 여백이 큰 에셋
- 적 1명과 2명 이상이 나오는 전투

선택 전환, 카드 사용, 피격, 적 행동, 사망 애니메이션 동안 링이 캐릭터와 따로 움직이거나 잔상으로 남지 않게 한다. 선택된 살아 있는 적 한 명에게만 표시하고, 대상이 쓰러지거나 바뀌면 즉시 새 상태와 일치시킨다. `aria-pressed`, 접근 가능한 선택 이름과 별도의 focus-visible은 유지한다. reduced-motion에서는 맥동 없이 동일한 정적 타원을 사용한다.

3. 이야기 이벤트 선택 결과 미리보기 숨김

`eventScreen`은 현재 각 이야기 선택 버튼에 `c.label` 아래 `<small>${c.text}</small>`을 표시한다. 이 `c.text`에는 `체력 +8`, `유대 +2`, `부담 -1`, `진화 에너지 +6`, `전용 카드 획득` 같은 실제 결과가 모두 노출된다.

모든 **이야기 이벤트 화면**에서는 선택하기 전에 이 기계적 결과 문자열을 표시하지 않는다.
- 버튼에는 `서로의 호흡에 맞춰 연습한다` 같은 서사적 선택 문장만 표시
- 정확한 수치, 획득 카드, 능력치 증감과 결과 요약을 `<small>`, tooltip, title, aria-label, 숨김 텍스트, hover, focus 또는 길게 누르기로 미리 노출하지 않음
- 선택지 문장 자체가 행동의 태도와 대략적인 위험을 자연스럽게 암시하도록 유지
- 단순히 `안전한 선택`, `위험한 선택`, `좋은 결과`처럼 정답을 직접 표시하는 메타 라벨을 새로 붙이지 않음
- 두 선택지가 구분되지 않거나 결과를 전혀 추론할 수 없는 장면은 `c.label`만 최소한으로 다듬되, 수치와 보상을 다시 넣지 않음

이 변경은 `eventScreen`에 한정한다. 캠프의 휴식/훈련, 진화 조건, 카드 설명과 전투처럼 자원 결과를 알아야 전략적으로 판단하는 UI는 이번 patch에서 숨기지 않는다. `Choice.text` 데이터는 선택 후 결과 알림, 문서 또는 콘텐츠 관리에 필요할 수 있으므로 데이터에서 무조건 삭제하지 말고 렌더링 경계를 수정한다.

선택한 뒤에는 실제 적용된 결과를 사용자가 이해할 수 있어야 한다. 기존에 선택 후 결과를 보여 주는 흐름이 있다면 그때만 `c.text`를 표시한다. 없다면 맵으로 돌아간 직후 한 번만 표시되는 짧은 결과 toast/요약을 추가해 실제 적용 결과를 알린다. 이 알림은 선택 **이후**에만 나타나고 자동 저장된 실제 변화와 일치해야 하며, aria-live로 읽을 수 있어야 한다. 선택 전 DOM이나 접근성 트리에 결과 문자열을 미리 넣어 두고 CSS로만 숨기는 방식은 사용하지 않는다.

선택 효과, 체력 0에 따른 패배, 카드 획득, story flag, 도감 기록, 노드 완료, 자동 저장과 난수 상태는 기존과 동일해야 한다. 이미 진행 중인 저장이나 v0.9 PWA standalone 저장도 schema 변경 없이 호환한다.

4. PWA 준비 시 모든 배경음악 선캐시

v0.9 구현은 앱 shell에 터치 효과음 7종의 MP3/OGG 14개만 넣고 음악은 runtime 지연 로드한다. v0.9.1에서는 `src/audio-manifest.json`에서 `kind === 'music'`인 모든 항목의 `files`를 빌드 시 자동 수집해 PWA의 필수 오프라인 캐시에 포함한다.

현재 기준 음악은 12곡의 MP3·OGG 두 포맷, 총 24개 파일이며 합계는 정확히 13,266,249바이트(약 12.65MiB)다. 파일명을 별도 배열에 다시 수기로 복사하지 말고 audio manifest를 단일 기준으로 삼아 이후 음악이 추가돼도 자동 포함되게 한다.

요구사항:
- 첫 service worker 설치/새 PWA 빌드 준비 과정에서 모든 `assets/audio/music/*.mp3`와 `*.ogg`를 내려받음
- 홈 화면 설치 후 네트워크를 끊어도 아직 방문하지 않은 지도·이야기·일반 전투·엘리트·각 보스 음악까지 재생 가능
- OGG 우선 브라우저와 MP3 fallback 브라우저를 모두 지원하기 위해 현재 manifest에 선언된 두 포맷 모두 포함
- 음악 파일 하나라도 필수 pack에 누락된 새 worker를 `오프라인 음악 준비 완료`로 표시하지 않음
- 새 캐시 구성이 실패하면 현재 활성 버전은 계속 동작하고 불완전한 새 worker로 교체하지 않음
- 변경되지 않은 음악은 content revision/hash를 비교해 다음 patch에서 불필요하게 다시 다운로드하지 않음
- 변경된 곡만 새 revision으로 교체하고 오래된 동일 앱 음악 캐시는 활성화 완료 뒤 안전하게 정리
- 음악 요청은 기존 AudioManager의 codec 선택, 재생 지연, 볼륨, 음소거와 3곡 decoded-buffer 제한을 그대로 사용함. 24곡을 한꺼번에 AudioContext로 decode하거나 메모리에 올리지 않음
- HTTP Cache Storage에 인코딩 파일을 보관하는 것과 Web Audio decoded buffer를 분리해 메모리 사용량을 늘리지 않음
- 저장 공간 부족, 네트워크 중단과 quota 오류가 발생하면 게임 저장 데이터를 지우지 않고 현재 활성 앱을 유지하며 다시 시도할 수 있는 상태를 제공

브라우저의 native `앱 설치` 승인 이벤트와 service worker의 install lifecycle은 같은 순간이 아닐 수 있다. 구현과 안내에서 이를 혼동해 `설치 버튼을 누른 뒤에만 다운로드된다`고 잘못 단정하지 않는다. 이 프로젝트에서는 첫 PWA 오프라인 본체를 준비할 때 음악 pack까지 함께 준비하고, 설정의 PWA 영역에서는 실제 활성 캐시 검증 결과에 따라 `오프라인 음악 준비됨` 또는 준비 실패/재시도 상태를 짧게 표시한다. 전투 화면이나 첫 페이지에 다운로드 홍보 배너를 추가하지 않는다.

현재 설정의 `그림·소리 캐시 복구`가 runtime cache만 비우는 정책을 재검토한다. 필수 음악을 shell/offline pack에 넣었다면 일반 복구 동작이 음악을 삭제해 놓고도 준비됐다고 표시하지 않아야 한다. 복구가 필수 음악을 유지하는 구조가 가장 단순하며, 음악 pack을 지울 수 있게 한다면 즉시 재다운로드·검증을 완료한 뒤 준비 상태를 갱신한다. localStorage, JSON 저장과 다른 앱 캐시는 절대 삭제하지 않는다.

`pwa-build.json`, PWA.md와 검증 문서에 다음을 기록한다.
- 선캐시 음악 파일 수와 바이트 합계
- 전체 필수 오프라인 캐시의 파일 수와 크기
- 음악 목록을 manifest에서 생성하는 방식
- 새 버전에서 변경되지 않은 곡 재사용 방식
- 저장 공간 부족/다운로드 실패 시 동작

5. 검증

- 디지몬의 최하단 접지부가 타원의 중심/뒤쪽 면과 겹쳐 실제로 링을 밟는지 스크린샷으로 비교

- 대상 변경, 카드 사용, 피격, 적 행동, 사망 후 링 상태와 위치 확인

## 완료 조건

- 선택된 상대 뒤의 네모난 오오라가 사라지고, 곡선형 오오라가 바닥 타원 내부에서 자연스럽게 위로 이어진다.
- 서로 다른 체형의 디지몬이 타원 위에 떠 있지 않고 실제 접지부로 링을 밟는 것처럼 보인다.
- 대상 전환과 애니메이션 중 링이 분리되거나 잘못된 적에게 남지 않으며 전투 UI 높이는 변하지 않는다.
- 이야기 이벤트 선택 전에는 정확한 능력치·보상 결과가 시각 UI와 접근성 트리에 노출되지 않는다.
- 선택지는 서사적으로 구분 가능하고, 선택 후에는 실제 적용 결과를 한 번 확인할 수 있다.
- PWA 준비가 끝나면 현재 24개·13,266,249바이트의 모든 MP3/OGG 음악이 캐시에 있고, 처음 들어가는 장면도 오프라인으로 재생된다.
- 음악 파일은 인코딩 상태로 캐시하며 한꺼번에 decode하지 않고, 변경되지 않은 곡은 후속 업데이트에서 다시 받지 않는다.
- 이야기 판정·저장과 캠프·진화·카드·전투 정보 및 v0.9 PWA 기능이 회귀하지 않는다.

구현 세션이 네모 오오라의 원인, 최종 타원 geometry와 레이어, 체형별 접지 offset, 선택·애니메이션·접근성 검증, 이야기 결과의 선택 전 비노출과 선택 후 알림, 판정 비교, 음악 선캐시 파일·크기·실패·증분 업데이트·오프라인 재생, PWA 회귀 및 구현 기준 커밋을 기록한다.
