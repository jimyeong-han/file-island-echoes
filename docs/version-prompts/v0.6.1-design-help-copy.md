# v0.6.1 — 디자인·도움말·문구 수정

- 상태: 예정
- 유형: 버그 수정
- 선행 버전: v0.6
- 제품 버전: `0.6.1`
- 작성일: 2026-09-10

## 증상

v0.6의 기능은 동작하지만 일부 시각 요소가 1999년 원작의 특징과 다르고, 캐릭터 카드의 능력 설명이 한 줄에 붙어 있어 읽기 어렵다. 상단의 정보 버튼이 자주 사용하는 도움말 자리를 차지하고 있으며 기존 도움말은 게임 규칙을 충분히 찾아볼 수 있는 구조가 아니다. 캐릭터 선택 안내 문구도 의도가 바로 전달되지 않는다.

## 기대 동작

- 여덟 문장의 로고가 각 문장의 원작 모티프를 알아볼 수 있는 독립적인 심볼로 표시된다.
- 장한솔의 노트북과 리키의 의상이 1999년 작품 시점의 외형 특징에 맞는다.
- 게임 로고에 디지바이스를 연상시키는 독자적인 장치 이미지가 사용된다.
- 지속 능력과 문장 능력의 이름·설명이 행을 나누어 읽힌다.
- 상단의 정보 위치에는 도움말이 있고, 정보는 페이지 하단에서 접근한다.
- 도움말은 책갈피형 챕터로 게임 방식, 성장 수치와 전투 효과를 오갈 수 있다.
- 캐릭터 선택 안내가 자연스럽고 구체적인 문장으로 바뀐다.

## 다른 세션에 전달할 프롬프트

```text
현재 저장소의 File Island Echoes v0.6에서 발견된 디자인·가독성·도움말 문제를 v0.6.1 patch로 수정해줘.

먼저 AGENTS.md, docs/version-prompts/README.md, docs/version-prompts/v0.6-digital-typography.md, README.md, TYPOGRAPHY.md, ASSETS.md, assets/ATTRIBUTION.md, docs/CANON-SOURCES.md와 현재 Git 상태를 확인한다. v0.6이 완료된 1444284 이후 상태를 기준으로 작업하고 기존 사용자 변경사항을 보존한다.

이 patch는 전투 수치, 카드 효과, 적 패턴, 진화 조건, 챕터 진행과 저장 데이터의 의미를 변경하지 않는다. 디자인 에셋, 설명 레이아웃, 도움말 탐색과 문구를 수정하는 범위다.

1. 문장 로고 디자인

현재 캐릭터별 문장 표시가 공격·방어·회복 같은 범용 게임 아이콘을 공유한다면, 용기·우정·사랑·지식·순수·성실·희망·빛을 위한 전용 문장 심볼 8개로 교체한다.

먼저 1999년 디지몬 어드벤처에서 각 문장이 가진 핵심 형태와 의미를 신뢰할 수 있는 자료로 확인한다. 확인한 자료와 반영한 시각 특징을 docs/CANON-SOURCES.md에 기록한다. 공식 이미지 파일을 저장소나 배포 에셋에 복사하지 않는다.

새 심볼은 원작 문장의 핵심 모티프를 알아볼 수 있게 하되 공식 벡터를 추출하거나 픽셀 단위로 트레이싱하지 않고 프로젝트용으로 직접 다시 그린다. 여덟 개 모두 같은 viewBox, 외곽 여백, 선 굵기, 발광 효과와 단색 사용 규칙을 적용한다.

권장 파일 구조:
- public/assets/ui/crest-courage.svg
- public/assets/ui/crest-friendship.svg
- public/assets/ui/crest-love.svg
- public/assets/ui/crest-knowledge.svg
- public/assets/ui/crest-purity.svg
- public/assets/ui/crest-reliability.svg
- public/assets/ui/crest-hope.svg
- public/assets/ui/crest-light.svg

실제 프로젝트 명칭과 ID 체계에 맞게 조정해도 된다. 파일 경로는 중앙 매니페스트 또는 문장 데이터에서 관리하고 화면 코드에 반복하지 않는다.

각 문장 심볼을 다음 위치에 일관되게 적용한다.
- 캐릭터 선택 카드
- 캐릭터 상세 화면
- 챕터 또는 개인 스토리의 문장 표시
- 전투 HUD와 문장 능력 버튼
- 문장 능력 상세 모달
- 도감의 캐릭터별 진행
- 도움말의 문장 설명

작은 20~24px 표시에서도 서로 구분되고, 단색·저채도·고대비 모드에서도 의미가 사라지지 않아야 한다. 장식용이면 aria-hidden을 사용하고, 정보 전달에 필요하면 “용기의 문장”처럼 접근 가능한 이름을 제공한다.

2. 장한솔의 노트북 재생성

현재 `portraits/koushiro-tentomon.webp`를 원본 해상도로 확인한다. 1999년 작품에서 장한솔이 사용하는 노트북의 다음 요소를 자료로 확인한다.
- 본체 색상과 전체 형태
- 화면과 키보드의 배치
- 덮개 또는 본체의 특징적인 표식
- 당시 휴대용 컴퓨터다운 두께와 비례
- 장한솔이 들거나 사용하는 방식

정확한 특징을 확인하지 않은 채 현대적인 얇은 노트북이나 임의의 게이밍 노트북으로 바꾸지 않는다. imagegen 스킬과 이미지 생성 도구를 사용해 장한솔·텐타몬 초상화를 기존 셀 셰이딩 화풍으로 다시 생성하거나 필요한 영역을 자연스럽게 편집한다.

장한솔의 얼굴, 연령, 텐타몬의 형태, 카메라 거리와 기존 구도는 가능한 한 유지하고 노트북이 손과 몸에 자연스럽게 연결되게 한다. 손가락, 힌지, 키보드, 화면 방향, 표식과 원근 오류를 원본 해상도에서 확인한다.

3. 리키의 원작 시점 의상 재생성

현재 `portraits/tk-patamon.webp`를 원본 해상도로 확인한다. 1999년 작품에서 리키가 착용한 모자, 상의, 하의, 신발, 색 조합과 액세서리를 신뢰할 수 있는 자료로 확인하고 docs/CANON-SOURCES.md에 기록한다.

imagegen 스킬과 이미지 생성 도구를 사용해 해당 의상 특징을 반영한 리키·파닥몬 초상화를 기존 화풍으로 재생성하거나 편집한다. 리키는 원작 시점의 어린 체구와 얼굴을 유지한다. 현대적인 의상, 성숙한 체형, 패션 화보 자세로 바꾸지 않는다.

파닥몬의 형태와 크기, 리키와의 상호작용, 기존 카메라 거리·배경·조명은 다른 초상화와 통일한다. 모자와 옷의 경계, 손발, 파닥몬의 귀·날개, 의도하지 않은 글자·서명·워터마크를 확인한다.

4. 디지바이스 모티프의 게임 로고

File Island Echoes의 게임 로고에 1999년 디지바이스를 연상시키는 장치 이미지를 새로 제작한다.

원작 장치의 둥근 휴대형 실루엣, 화면, 버튼과 디지털 파동이라는 핵심 인상을 반영하되 공식 로고나 디지바이스 이미지를 그대로 복사·트레이싱하지 않는다. 프로젝트만의 회로, 파일섬 신호 또는 데이터 균열 모티프를 더해 독자적인 팬게임 엠블럼으로 만든다.

이미지 생성 결과 안에 게임 제목 글자를 억지로 생성하지 않는다. 장치 엠블럼은 투명 배경 이미지 또는 정돈된 SVG로 만들고, `File Island Echoes`와 `파일섬의 잔향` 텍스트는 v0.6의 로컬 폰트와 HTML/CSS 또는 별도 벡터 조판으로 선명하게 구성한다. 공식 Digimon 워드마크의 글자 형태를 복제하지 않는다.

로고는 다음 환경에서 사용 가능한 변형을 제공한다.
- 타이틀 화면의 가로형 또는 결합형 로고
- 좁은 모바일 화면
- 작은 헤더 또는 로딩 표시
- 파비콘/앱 아이콘에 사용할 수 있는 텍스트 없는 장치 심볼

타이틀의 기존 접근 가능한 h1은 유지한다. 이미지 로드 실패 시에도 게임 이름이 보이고, 로고 때문에 초기 로딩 용량이 과도하게 늘지 않게 한다.

5. 신규·교체 에셋 공통 규칙

- 공식 애니메이션 캡처, 공식 게임 추출 스프라이트·벡터·로고를 저장소에 포함하지 않는다.
- 자료는 형태와 의상 확인에만 사용하고 새 에셋은 프로젝트용으로 직접 제작한다.
- 기존 640×640 초상화 규격과 WebP 최적화 기준을 유지한다.
- 교체 전후 이미지를 실제 게임 화면에서 비교한다.
- asset manifest, ASSETS.md, assets/ATTRIBUTION.md와 생성 프롬프트 기록을 갱신한다.
- 이전 파일을 제거하기 전 모든 참조가 교체됐는지 확인한다.
- 브라우저 캐시로 이전 그림이 남지 않도록 파일명 또는 빌드 해시 동작을 확인한다.

6. 지속 능력·문장 능력 설명 가독성

캐릭터 선택 카드의 “지속 능력 · 문장 능력” 상세 영역에서 라벨과 설명을 같은 행에 붙이지 않는다.

현재와 같은 형태:
`지속  에너지 3 이상에서...`

다음처럼 의미상 분리된 블록으로 표시한다.

지속

에너지 3 이상에서 쓰는 턴의 첫 공격에 피해가 추가됩니다.

문장 능력 · 용기의 결단

부담을 얻는 대신 이번 턴의 공격과 진화 에너지를 강화합니다.

HTML 문자열에 `<br>`만 넣어 모양을 맞추지 말고, 제목과 설명을 각각 의미 있는 요소로 구성한다. 예:
- 능력 종류 또는 이름: strong, dt, h3 등
- 설명: p 또는 dd
- 발동 조건: 별도 small/p

다음 위치에서 같은 정보 구조를 확인한다.
- 캐릭터 선택 카드의 접이식 설명
- 캐릭터 상세
- 전투 HUD의 능력 상세
- 도움말의 캐릭터/문장 설명

모바일에서 설명 사이 간격은 분명하지만 카드가 지나치게 길어지지 않게 한다. 스크린리더가 “지속”, 설명, “문장 능력”, 설명 순서로 자연스럽게 읽어야 한다.

7. 상단 도움말과 하단 정보

현재 상단 헤더 또는 빠른 메뉴의 “정보” 위치를 “도움말”로 교체한다. 사용 빈도가 높은 도움말은 모든 주요 화면에서 같은 위치로 접근할 수 있어야 한다.

기존 정보 내용과 비공식 팬 프로젝트 고지를 삭제하지 않는다. “정보” 접근 버튼 또는 링크를 공통 페이지의 맨 아래 footer 영역으로 이동한다. 긴 게임 화면에서도 콘텐츠 뒤에 footer가 배치되고 키보드로 접근 가능해야 한다. 화면 하단 고정 버튼으로 게임 조작을 가리지 않는다.

기존 `help`와 `credits`/정보 모달이 중복되면 역할을 정리한다.
- 도움말: 플레이 규칙과 용어 사전
- 정보: 프로젝트 설명, 비공식·비영리 고지, 에셋/폰트/오디오 크레딧과 버전

도움말을 책의 책갈피처럼 보이는 챕터 탭으로 구성한다. 최소 챕터:

A. 게임 방법
- 캐릭터와 챕터 선택
- 노드 지도와 갈림길
- 일반 전투, 강적, 이벤트, 휴식과 보스
- 턴마다 에너지 3과 카드 5장
- 카드 사용, 대상 선택, 턴 종료와 적 행동 예고
- 전투 보상과 카드 건너뛰기
- 패배, 재도전과 챕터 진행

B. 성장과 상태 수치
- 체력과 방어도
- 진화 에너지와 진화 조건
- 유대
- 부담
- 오염
- 보급품
- 문장 능력의 조건과 전투당 사용 횟수
- 일반 진화, 강제 진화와 가트몬의 빛의 공명

C. 전투 효과와 카드 용어
- 연계
- 방어
- 노출
- 표식
- 화상
- 약화
- 감전
- 속박
- 정화
- 재생
- 비축
- 희망
- 빛
- 소멸
- 봉인
- 추가 비용과 현재 게임에 실제 존재하는 나머지 키워드

설명은 `src/content/cards.ts`의 KEYWORDS와 실제 엔진 동작을 기준으로 작성한다. 같은 용어 정의를 여러 곳에 서로 다르게 하드코딩하지 않는다. 가능하면 도움말 데이터 모델에서 챕터와 항목을 관리하고 기존 키워드 사전을 재사용한다.

책갈피 UI 요구사항:
- 세 챕터를 탭/책갈피로 바로 전환
- 현재 선택된 챕터가 시각적·텍스트로 구분
- 키보드 방향키, Home/End와 Enter/Space 지원 또는 동등하게 접근 가능한 버튼 탐색
- 적절한 tablist/tab/tabpanel ARIA 적용
- 도움말을 닫았다 다시 열 때 최소한 같은 실행 중에는 마지막 챕터 유지
- 각 패널 제목에 포커스를 옮기거나 변경 내용을 스크린리더에 알림
- 320px 모바일에서는 책갈피가 잘리거나 가로 문서 넘침을 만들지 않음
- 본문이 길면 모달 내부 스크롤을 제공하고 닫기 버튼은 찾기 쉬운 위치 유지

8. 캐릭터 선택 안내 문구

다음 문구를 코드와 빌드 결과에서 제거한다.

`문장이 강요하는 정답은 없습니다. 파트너와 어떤 방식으로 싸우고 성장할지 골라 보세요.`

다음 문구로 변경한다.

`어떤 캐릭터로 플레이할지 골라 보세요. 파트너 디지몬과 문장에 따라 플레이 스타일이 달라집니다.`

비슷한 이전 문구가 다른 파일에 중복되어 있으면 함께 정리한다. 새 문구의 의미를 임의로 철학적인 설명으로 확장하지 않는다.
```

## 완료 조건

- 여덟 문장에 전용 심볼이 있고 모든 관련 화면에서 올바르게 연결된다.
- 장한솔의 노트북과 리키의 의상이 확인한 1999년 작품 특징을 반영한다.
- 디지바이스 모티프의 독자적인 게임 로고가 타이틀·모바일·작은 아이콘에서 동작한다.
- 지속 및 문장 능력의 제목과 설명이 별도 행으로 표시된다.
- 상단에는 도움말, 공통 페이지 하단에는 정보 접근점이 있다.
- 도움말의 세 책갈피가 터치·마우스·키보드로 전환되고 실제 규칙과 일치한다.
- 캐릭터 선택 안내 문구가 지정 문장으로 변경되고 이전 문구가 남지 않는다.
- 기존 전투·저장·오디오와 Pages 빌드가 회귀하지 않는다.
