# v0.6.1 — 디자인·도움말·문구 수정

- 상태: 예정
- 유형: 버그 수정
- 선행 버전: v0.6
- 제품 버전: `0.6.1`
- 작성일: 2026-09-10

## 증상

v0.6의 기능은 동작하지만 일부 시각 요소가 1999년 원작의 특징과 다르고, 캐릭터 카드의 능력 설명이 한 줄에 붙어 있어 읽기 어렵다. 상단의 정보 버튼이 자주 사용하는 도움말 자리를 차지하고 있으며 기존 도움말은 게임 규칙을 충분히 찾아볼 수 있는 구조가 아니다. 캐릭터 선택 안내 문구도 의도가 바로 전달되지 않는다. 갤럭시 S23+에서는 전투 중 HUD의 `에너지` 글자가 두 줄로 나뉜다. 상단의 소리 버튼이 `소리 켜짐`과 `음소거` 사이에서 바뀔 때 너비가 달라져 인접한 도감 버튼의 위치가 움직이며, 첫 화면의 플레이 시간·자동 저장 문구는 지나치게 생성형 문구처럼 느껴진다. 신나리·가트몬 초상화에서는 가트몬의 얼굴 방향과 몸 방향이 맞지 않아 자세가 부자연스럽고, 신나리의 머리가 원작 시점의 숏컷이 아닌 단발로 표기되거나 표현된 문제가 있다.

## 기대 동작

- 여덟 문장의 로고가 각 문장의 원작 모티프를 알아볼 수 있는 독립적인 심볼로 표시된다.
- 장한솔의 노트북과 리키의 의상이 1999년 작품 시점의 외형 특징에 맞는다.
- 게임 로고에 디지바이스를 연상시키는 독자적인 장치 이미지가 사용된다.
- 지속 능력과 문장 능력의 이름·설명이 행을 나누어 읽힌다.
- 상단의 정보 위치에는 도움말이 있고, 정보는 페이지 하단에서 접근한다.
- 도움말은 책갈피형 챕터로 게임 방식, 성장 수치와 전투 효과를 오갈 수 있다.
- 캐릭터 선택 안내가 자연스럽고 구체적인 문장으로 바뀐다.
- 갤럭시 S23+의 전투 화면에서 `에너지` 라벨이 한 줄로 표시되고 주변 HUD와 겹치지 않는다.
- 소리 상태를 전환해도 상단 도감 버튼의 위치가 움직이지 않는다.
- 첫 화면의 플레이 시간과 자동 저장 안내가 간결하고 자연스러운 문장으로 표시된다.
- 가트몬의 얼굴·목·몸통 방향이 해부학적으로 자연스럽게 연결되고, 신나리의 머리는 단발이 아닌 원작 시점의 숏컷으로 표현된다.

## 다른 세션에 전달할 프롬프트

```text
현재 저장소의 File Island Echoes v0.6에서 발견된 디자인·가독성·도움말 문제를 v0.6.1 patch로 수정해줘.

먼저 AGENTS.md, docs/version-prompts/README.md, docs/version-prompts/v0.6-digital-typography.md, README.md, TYPOGRAPHY.md, ASSETS.md, assets/ATTRIBUTION.md, docs/CANON-SOURCES.md와 현재 Git 상태를 확인한다. v0.6이 완료된 1444284 이후 상태를 기준으로 작업하고 기존 사용자 변경사항을 보존한다.

이 patch는 전투 수치, 카드 효과, 적 패턴, 진화 조건, 챕터 진행과 저장 데이터의 의미를 변경하지 않는다. 디자인 에셋, 설명 레이아웃, 도움말 탐색과 문구를 수정하는 범위다.

1. 문장 로고 디자인

현재 캐릭터별 문장 표시가 공격·방어·회복 같은 범용 게임 아이콘을 공유한다면, 용기·우정·사랑·지식·순수·성실·희망·빛을 위한 전용 문장 심볼 8개로 교체한다.

먼저 1999년 디지몬 어드벤처에서 각 문장이 가진 핵심 형태와 의미를 신뢰할 수 있는 자료로 확인한다. 확인한 자료와 반영한 시각 특징을 docs/CANON-SOURCES.md에 기록한다. 공식 이미지 파일을 저장소나 배포 에셋에 복사하지 않는다.

새 심볼은 원작 문장의 핵심 모티프를 알아볼 수 있게 하되 공식 벡터를 추출하거나 픽셀 단위로 트레이싱하지 않고 프로젝트용으로 직접 다시 그린다. 여덟 개 모두 같은 viewBox, 외곽 여백, 선 굵기, 발광 효과와 단색 사용 규칙을 적용한다.

권장 파일 구조:
- public/assets/ui/crest-courage.svg
- public/assets/ui/crest-friendship.svg
- public/assets/ui/crest-love.svg
- public/assets/ui/crest-knowledge.svg
- public/assets/ui/crest-purity.svg
- public/assets/ui/crest-reliability.svg
- public/assets/ui/crest-hope.svg
- public/assets/ui/crest-light.svg

실제 프로젝트 명칭과 ID 체계에 맞게 조정해도 된다. 파일 경로는 중앙 매니페스트 또는 문장 데이터에서 관리하고 화면 코드에 반복하지 않는다.

각 문장 심볼을 다음 위치에 일관되게 적용한다.
- 캐릭터 선택 카드
- 캐릭터 상세 화면
- 챕터 또는 개인 스토리의 문장 표시
- 전투 HUD와 문장 능력 버튼
- 문장 능력 상세 모달
- 도감의 캐릭터별 진행
- 도움말의 문장 설명

작은 20~24px 표시에서도 서로 구분되고, 단색·저채도·고대비 모드에서도 의미가 사라지지 않아야 한다. 장식용이면 aria-hidden을 사용하고, 정보 전달에 필요하면 “용기의 문장”처럼 접근 가능한 이름을 제공한다.

2. 장한솔의 노트북 재생성

현재 `portraits/koushiro-tentomon.webp`를 원본 해상도로 확인한다. 사용자가 제공한 애니메이션 참고 이미지를 우선적인 시각 기준으로 삼되, 참고 이미지 자체를 저장소에 복사하거나 새 에셋에 그대로 트레이싱하지 않는다. 다른 세션에서 이미지 파일을 열 수 없더라도 아래 체크리스트만으로 핵심 특징을 재현할 수 있어야 한다.

- 현대적인 얇은 제품이 아니라 크고 두꺼운 초기 휴대용 컴퓨터형 클램셸 본체
- 덮개와 본체의 주조색은 채도가 낮은 옅은 민트·시폼 그린
- 덮개 아래쪽 좌우 모서리를 감싸는 큼직한 머스터드 옐로 패널
- 덮개 위쪽 중앙의 노란 직사각형 래치 또는 힌지 포인트
- 덮개 아래쪽 중앙에 있는 작고 단순한 노란 파인애플 그림. 공식 캡처에서 표식을 추출해 붙이지 말고 참고 이미지의 크기·위치·색 인상을 바탕으로 새로 그린다.
- 넓은 덮개와 묵직한 베젤, 당시 장비다운 두께와 비례
- 화면과 키보드의 방향, 장한솔이 앞에 펼쳐 놓고 내려다보며 사용하는 자세
- 장한솔의 의상이 함께 보인다면 주황색 긴소매 상의와 노란 장갑의 인상을 유지

정확한 특징을 확인하지 않은 채 현대적인 얇은 노트북이나 임의의 게이밍 노트북으로 바꾸지 않는다. imagegen 스킬과 이미지 생성 도구를 사용해 장한솔·텐타몬 초상화를 기존 셀 셰이딩 화풍으로 다시 생성하거나 필요한 영역을 자연스럽게 편집한다.

장한솔의 얼굴, 연령, 텐타몬의 형태, 카메라 거리와 기존 구도는 가능한 한 유지하고 노트북이 손과 몸에 자연스럽게 연결되게 한다. 손가락, 힌지, 키보드, 화면 방향, 표식과 원근 오류를 원본 해상도에서 확인한다.

3. 리키의 원작 시점 의상 재생성

현재 `portraits/tk-patamon.webp`를 원본 해상도로 확인한다. 사용자가 제공한 전신 캐릭터 참고 이미지를 우선적인 시각 기준으로 삼되, 참고 이미지 자체를 저장소에 복사하거나 새 에셋에 그대로 트레이싱하지 않는다. 다음 특징을 구현 체크리스트로 사용한다.

- 금발 앞머리와 원작 시점의 어린아이다운 작은 체구, 큰 머리 비례와 둥근 얼굴
- 양옆이 귀덮개처럼 크게 내려오는 짙은 초록색 모자
- 모자 전면을 가로지르는 라임·연노랑 사선 띠와 중앙 위쪽의 파란 타원형 장식
- 밝은 초록색 긴소매 상의와 그보다 짙은 초록색 중앙 몸판
- 무릎 길이의 황갈색·갈색 반바지
- 노란 양말 또는 발목 커프
- 흰색의 두꺼운 밑창과 초록·청록색 패널이 조합된 볼륨감 있는 운동화
- 밝고 친근한 표정과 아동 캐릭터다운 자연스러운 자세

위 체크리스트를 1999년 작품의 모자, 상의, 하의, 신발과 색 조합을 확인하는 기준으로 사용하고, 구현 중 추가로 확인한 출처가 있다면 docs/CANON-SOURCES.md에 기록한다.

imagegen 스킬과 이미지 생성 도구를 사용해 해당 의상 특징을 반영한 리키·파닥몬 초상화를 기존 화풍으로 재생성하거나 편집한다. 리키는 원작 시점의 어린 체구와 얼굴을 유지한다. 현대적인 의상, 성숙한 체형, 패션 화보 자세로 바꾸지 않는다.

파닥몬의 형태와 크기, 리키와의 상호작용, 기존 카메라 거리·배경·조명은 다른 초상화와 통일한다. 모자와 옷의 경계, 손발, 파닥몬의 귀·날개, 의도하지 않은 글자·서명·워터마크를 확인한다.

4. 디지바이스 모티프의 게임 로고

File Island Echoes의 게임 로고에 1999년 디지바이스를 연상시키는 장치 이미지를 새로 제작한다.

원작 장치의 둥근 휴대형 실루엣, 화면, 버튼과 디지털 파동이라는 핵심 인상을 반영하되 공식 로고나 디지바이스 이미지를 그대로 복사·트레이싱하지 않는다. 프로젝트만의 회로, 파일섬 신호 또는 데이터 균열 모티프를 더해 독자적인 팬게임 엠블럼으로 만든다.

이미지 생성 결과 안에 게임 제목 글자를 억지로 생성하지 않는다. 장치 엠블럼은 투명 배경 이미지 또는 정돈된 SVG로 만들고, `File Island Echoes`와 `파일섬의 잔향` 텍스트는 v0.6의 로컬 폰트와 HTML/CSS 또는 별도 벡터 조판으로 선명하게 구성한다. 공식 Digimon 워드마크의 글자 형태를 복제하지 않는다.

로고는 다음 환경에서 사용 가능한 변형을 제공한다.
- 타이틀 화면의 가로형 또는 결합형 로고
- 좁은 모바일 화면
- 작은 헤더 또는 로딩 표시
- 파비콘/앱 아이콘에 사용할 수 있는 텍스트 없는 장치 심볼

타이틀의 기존 접근 가능한 h1은 유지한다. 이미지 로드 실패 시에도 게임 이름이 보이고, 로고 때문에 초기 로딩 용량이 과도하게 늘지 않게 한다.

5. 신규·교체 에셋 공통 규칙

- 공식 애니메이션 캡처, 공식 게임 추출 스프라이트·벡터·로고를 저장소에 포함하지 않는다.
- 자료는 형태와 의상 확인에만 사용하고 새 에셋은 프로젝트용으로 직접 제작한다.
- 기존 640×640 초상화 규격과 WebP 최적화 기준을 유지한다.
- 교체 전후 이미지를 실제 게임 화면에서 비교한다.
- asset manifest, ASSETS.md, assets/ATTRIBUTION.md와 생성 프롬프트 기록을 갱신한다.
- 이전 파일을 제거하기 전 모든 참조가 교체됐는지 확인한다.
- 브라우저 캐시로 이전 그림이 남지 않도록 파일명 또는 빌드 해시 동작을 확인한다.

6. 지속 능력·문장 능력 설명 가독성

캐릭터 선택 카드의 “지속 능력 · 문장 능력” 상세 영역에서 라벨과 설명을 같은 행에 붙이지 않는다.

현재와 같은 형태:
`지속  에너지 3 이상에서...`

다음처럼 의미상 분리된 블록으로 표시한다.

지속

에너지 3 이상에서 쓰는 턴의 첫 공격에 피해가 추가됩니다.

문장 능력 · 용기의 결단

부담을 얻는 대신 이번 턴의 공격과 진화 에너지를 강화합니다.

HTML 문자열에 `<br>`만 넣어 모양을 맞추지 말고, 제목과 설명을 각각 의미 있는 요소로 구성한다. 예:
- 능력 종류 또는 이름: strong, dt, h3 등
- 설명: p 또는 dd
- 발동 조건: 별도 small/p

다음 위치에서 같은 정보 구조를 확인한다.
- 캐릭터 선택 카드의 접이식 설명
- 캐릭터 상세
- 전투 HUD의 능력 상세
- 도움말의 캐릭터/문장 설명

모바일에서 설명 사이 간격은 분명하지만 카드가 지나치게 길어지지 않게 한다. 스크린리더가 “지속”, 설명, “문장 능력”, 설명 순서로 자연스럽게 읽어야 한다.

7. 상단 도움말과 하단 정보

현재 상단 헤더 또는 빠른 메뉴의 “정보” 위치를 “도움말”로 교체한다. 사용 빈도가 높은 도움말은 모든 주요 화면에서 같은 위치로 접근할 수 있어야 한다.

기존 정보 내용과 비공식 팬 프로젝트 고지를 삭제하지 않는다. “정보” 접근 버튼 또는 링크를 공통 페이지의 맨 아래 footer 영역으로 이동한다. 긴 게임 화면에서도 콘텐츠 뒤에 footer가 배치되고 키보드로 접근 가능해야 한다. 화면 하단 고정 버튼으로 게임 조작을 가리지 않는다.

기존 `help`와 `credits`/정보 모달이 중복되면 역할을 정리한다.
- 도움말: 플레이 규칙과 용어 사전
- 정보: 프로젝트 설명, 비공식·비영리 고지, 에셋/폰트/오디오 크레딧과 버전

도움말을 책의 책갈피처럼 보이는 챕터 탭으로 구성한다. 최소 챕터:

A. 게임 방법
- 캐릭터와 챕터 선택
- 노드 지도와 갈림길

- 턴마다 에너지 3과 카드 5장
- 카드 사용, 대상 선택, 턴 종료와 적 행동 예고
- 전투 보상과 카드 건너뛰기
- 패배, 재도전과 챕터 진행

B. 성장과 상태 수치

- 화상

설명은 `src/content/cards.ts`의 KEYWORDS와 실제 엔진 동작을 기준으로 작성한다. 같은 용어 정의를 여러 곳에 서로 다르게 하드코딩하지 않는다. 가능하면 도움말 데이터 모델에서 챕터와 항목을 관리하고 기존 키워드 사전을 재사용한다.

책갈피 UI 요구사항:
- 세 챕터를 탭/책갈피로 바로 전환
- 현재 선택된 챕터가 시각적·텍스트로 구분
- 키보드 방향키, Home/End와 Enter/Space 지원 또는 동등하게 접근 가능한 버튼 탐색
- 적절한 tablist/tab/tabpanel ARIA 적용
- 도움말을 닫았다 다시 열 때 최소한 같은 실행 중에는 마지막 챕터 유지
- 각 패널 제목에 포커스를 옮기거나 변경 내용을 스크린리더에 알림
- 320px 모바일에서는 책갈피가 잘리거나 가로 문서 넘침을 만들지 않음
- 본문이 길면 모달 내부 스크롤을 제공하고 닫기 버튼은 찾기 쉬운 위치 유지

8. 캐릭터 선택 안내 문구

다음 문구를 코드와 빌드 결과에서 제거한다.

`문장이 강요하는 정답은 없습니다. 파트너와 어떤 방식으로 싸우고 성장할지 골라 보세요.`

다음 문구로 변경한다.

`어떤 캐릭터로 플레이할지 골라 보세요. 파트너 디지몬과 문장에 따라 플레이 스타일이 달라집니다.`

비슷한 이전 문구가 다른 파일에 중복되어 있으면 함께 정리한다. 새 문구의 의미를 임의로 철학적인 설명으로 확장하지 않는다.

9. 갤럭시 S23+ 전투 HUD의 에너지 줄바꿈 수정

갤럭시 S23+에서 실제 전투에 진입하면 HUD의 `에너지` 라벨이 글자 중간에서 줄바꿈되는 문제를 재현하고 원인을 확인한다. 단순히 글자 크기를 과도하게 줄이거나 라벨을 `E`처럼 축약하지 말고, 해당 HUD 행의 flex/grid 축소 규칙, 사용 가능한 너비, 아이콘·현재값·최대값과의 간격 및 한국어 줄바꿈 규칙을 함께 점검한다.

수정 요구사항:
- `에너지` 네 글자는 세로 모드와 가로 모드 모두 항상 한 줄로 표시
- 에너지 아이콘, 현재/최대 수치와 라벨 사이의 시각적 관계 유지
- HUD의 체력, 방어도, 진화 에너지, 턴 정보 또는 조작 버튼과 겹치지 않음
- 화면 전체에 가로 스크롤이나 잘림이 생기지 않음
- 큰 수치, 두 자리 이상의 에너지 값과 200% 확대에서도 레이아웃이 무너지지 않음
- 한국어 이외 로케일 또는 긴 대체 텍스트가 있다면 기존 반응형 동작을 악화시키지 않음

실제 갤럭시 S23+ 확인을 최우선으로 하고, 개발자 도구에서는 브라우저 UI를 제외한 실제 CSS viewport를 측정해 같은 너비로 재현한다. 기기 프리셋이 없으면 약 384px 너비의 모바일 viewport를 기본 회귀 조건으로 사용하되, 실제 측정값이 다르면 측정값을 VALIDATION.md에 기록한다. `white-space: nowrap`이 필요할 수 있지만 그것만 덧붙여 주변 요소를 밀어내는 방식으로 끝내지 말고 좁은 폭 전체의 배치를 함께 검증한다.

10. 소리 버튼 전환 시 도감 위치 고정

상단의 소리 버튼을 터치해 `소리 켜짐`과 `음소거` 상태를 오갈 때 버튼 폭이 달라지면서 인접한 도감 버튼이 좌우로 움직이는 문제를 재현하고 수정한다. 사용자가 연속으로 소리를 전환해도 도감의 위치와 터치 영역은 고정되어야 한다.

우선 두 상태를 모두 수용하는 안정적인 버튼 너비 또는 툴바 열 너비를 확보하고, 아이콘·라벨·간격을 포함한 헤더 레이아웃이 상태에 따라 재배치되지 않게 한다. 좁은 화면에서 공간이 부족하다면 도감 버튼을 소리 버튼보다 앞의 고정 열로 옮기는 대안도 허용한다. 어떤 방식을 택하든 다음 조건을 지킨다.

- 소리 전환 전후 도감 버튼의 위치와 터치 영역이 변하지 않음
- `소리 켜짐`과 `음소거`의 현재 상태가 시각적으로 명확함
- 버튼의 접근 가능한 이름과 `aria-pressed` 등 기존 상태 전달을 유지
- 텍스트를 숨기는 모바일 표현을 사용한다면 아이콘만으로 상태를 구분하고 스크린리더 이름은 유지
- 도움말·도감·소리 버튼이 320px 폭에서도 겹치거나 화면 밖으로 나가지 않음
- 터치 직후 효과음 반응과 실제 음소거 기능은 회귀하지 않음

11. 첫 화면 플레이 안내 문구 개선

첫 페이지에서 `한 번의 탐험`, `약 10-15분`, `자동저장`을 조합해 표시하는 기존 문구를 찾아 제거하고, 다음 문장으로 교체한다.

`한 판은 약 10~15분이며, 진행 상황은 자동으로 저장됩니다.`

한국어 범위 표기는 하이픈 대신 물결표 `~`를 사용하고 `자동 저장`은 띄어 쓴다. 의미를 부풀리는 홍보성·시적 표현이나 불필요한 부제는 추가하지 않는다. 현재 UI가 두 개 이상의 배지나 행으로 분리되어 있다면 문장을 억지로 다시 쪼개지 말고 한 개의 안내 문장으로 읽히게 구성하되, 모바일에서도 어색한 단어 단위 줄바꿈이 생기지 않게 한다.

12. 신나리·가트몬 초상화 자세와 헤어스타일 수정

현재 `portraits/kari-gatomon-adventure.webp`를 원본 해상도로 확인한다. 가트몬의 얼굴이 바라보는 방향과 목·어깨·가슴·앞발을 포함한 몸통 방향이 서로 다르게 회전해 붙어 보이는 문제를 수정한다. 단순히 얼굴만 회전하거나 몸을 뒤집지 말고 캐릭터 전체의 포즈와 무게중심을 다시 잡는다.

가트몬 자세 요구사항:
- 얼굴에서 목, 어깨, 등과 몸통으로 이어지는 축이 자연스러움
- 시선과 고개 회전 범위가 몸의 자세로 설명 가능함
- 앞발·뒷발의 접지와 몸의 무게중심이 일치함
- 귀, 꼬리와 장갑의 좌우 관계가 포즈 및 원근과 맞음
- 신나리와 가트몬이 서로 바라보거나 같은 방향을 보는 구도라면 시선 관계가 명확함
- 얼굴이나 몸 한쪽만 편집한 흔적, 관절 단절, 좌우 반전 오류와 겹친 윤곽이 없음

신나리의 헤어스타일은 `단발`, `단발머리` 또는 턱선까지 내려오는 보브컷으로 정의하지 않는다. 원작 1999년 시점에 가까운 `숏컷에 가까운 짧은 머리`로 수정한다. 귀와 목 주변이 비교적 드러나는 짧은 길이, 가볍게 갈라진 앞머리와 머리에 붙는 아동다운 실루엣을 기준으로 삼고, 턱 아래로 내려오는 묵직한 단발이나 성숙한 보브 스타일을 피한다.

소스 코드, 에셋 설명, 생성 프롬프트, ASSETS.md와 관련 문서에서 신나리 헤어스타일을 `단발`로 잘못 적은 곳이 있는지 검색해 같은 기준으로 정정한다. 현재 이미지 자체도 단발처럼 보이면 imagegen 스킬과 이미지 생성 도구로 해당 초상화를 다시 생성하거나 편집한다. 기존의 어린 얼굴·작은 체구, 연노란 상의, 분홍 스카프·반바지, 호루라기 모티프와 셀 셰이딩 화풍은 유지한다. 공식 이미지를 복사하거나 트레이싱하지 않는다.
```

## 완료 조건

- 여덟 문장에 전용 심볼이 있고 모든 관련 화면에서 올바르게 연결된다.

- 지속 및 문장 능력의 제목과 설명이 별도 행으로 표시된다.
- 상단에는 도움말, 공통 페이지 하단에는 정보 접근점이 있다.
- 도움말의 세 책갈피가 터치·마우스·키보드로 전환되고 실제 규칙과 일치한다.
- 캐릭터 선택 안내 문구가 지정 문장으로 변경되고 이전 문구가 남지 않는다.
- 갤럭시 S23+ 전투 HUD에서 `에너지` 라벨이 줄바꿈되지 않고 인접 요소와 겹치지 않는다.
- 소리 상태를 반복해서 전환해도 도감 버튼의 위치와 터치 영역이 고정된다.
- 첫 화면에 `한 판은 약 10~15분이며, 진행 상황은 자동으로 저장됩니다.`가 자연스럽게 표시된다.
- 가트몬의 얼굴과 몸 방향이 자연스럽게 연결되고 발과 몸의 무게중심이 맞는다.
- 신나리의 헤어스타일이 단발이 아닌 원작 시점의 숏컷으로 표현·기록된다.
- 기존 전투·저장·오디오와 Pages 빌드가 회귀하지 않는다.
