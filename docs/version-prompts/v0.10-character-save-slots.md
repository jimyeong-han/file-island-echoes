# v0.10 — 선택받은 아이별 이어하기

- 상태: 예정
- 유형: 기능 버전
- 선행 버전: v0.9.1
- 제품 버전: `0.10.0`
- 작성일: 2026-09-11

## 목표

8명의 선택받은 아이가 각자 하나의 독립된 진행 슬롯을 갖게 한다. 리키로 탐험하다가 신나리의 새 탐험을 시작하고, 나중에 다시 리키를 선택하면 리키가 마지막으로 저장된 장소·전투 상태에서 그대로 이어진다. 도감·해금·설정은 지금처럼 전체 프로필에서 공유한다.

## 다른 세션에 전달할 프롬프트

```text
현재 저장소의 File Island Echoes v0.9.1을 v0.10으로 업데이트해 선택받은 아이별 독립 이어하기 기능을 설계하고 구현해줘.

먼저 AGENTS.md, docs/version-prompts/README.md, v0.7 저장 관리 문서와 검증 기록, v0.9 PWA와 v0.9.1 문서, `src/types.ts`, `src/storage.ts`, `src/save-files.ts`, `src/save-files-ui.ts`, `src/main.ts`, 저장·엔진·PWA 테스트와 Git 상태를 확인한다. v0.9.1이 완료되지 않았다면 먼저 버전 순서대로 완료한다. 기존 사용자 변경사항을 보존한다.

현재 `Save`는 `version: 2`와 단일 `run: Run | null`만 가지므로 새 캐릭터로 출발하면 기존 탐험을 교체한다. v0.10에서는 8명의 캐릭터가 각자 최대 한 개의 독립된 탐험을 보관하고, 타이틀이나 캐릭터 선택 화면에서 원하는 탐험으로 전환해 이어갈 수 있게 한다.

대표 사용자 경로는 다음과 같다.
1. 리키로 파일섬 탐험을 시작해 전투 중 또는 지도에서 자동 저장
2. 타이틀로 돌아가 신나리를 선택하고 별도의 새 탐험 시작
3. 신나리 진행 중 타이틀로 돌아가 리키의 `이어하기` 선택
4. 리키가 이전에 저장된 챕터, 노드, 체력, 진화, 덱과 전투 턴 그대로 복원
5. 다시 신나리로 전환해도 신나리 진행 역시 그대로 유지

1. 저장 모델 설계

임시로 현재 `save.run`을 바꿔 끼우며 다른 진행을 별도 localStorage key에 흩어 놓는 방식은 사용하지 않는다. 한 번의 원자적 저장으로 전체 프로필과 모든 슬롯이 일관되게 기록되는 정규화된 새 schema를 설계한다.

권장 구조:
```ts
interface RunSlot {
  run: Run;
  updatedAt: number;
}

interface Save {
  version: 3;
  runs: Partial<Record<CharacterId, RunSlot>>;
  activeCharacterId: CharacterId | null;
  archive: Archive;
  settings: Settings;
}
```

구조를 약간 다르게 정할 수는 있지만 다음 불변 조건은 지킨다.
- 슬롯 key와 `run.characterId`가 반드시 같음
- 캐릭터당 슬롯은 최대 1개이며 총 8개를 넘지 않음
- 현재 플레이 중인 슬롯은 하나뿐이고 `activeCharacterId`가 존재하는 슬롯만 가리킴
- `updatedAt`은 유효한 timestamp이며 실제 성공한 진행 저장 때 갱신
- 도감, 클리어·엔딩, 누적 통계와 설정은 슬롯마다 복제하지 않고 공용 유지
- `Archive.runs`처럼 기존 누적 완료 횟수와 새 `Save.runs` 슬롯 컬렉션을 코드에서 혼동하지 않도록 이름·타입·도우미를 명확히 함
- 단일 `run`과 `runs`를 동시에 영구 저장해 두 개의 source of truth를 만들지 않음

`activeRun(save)`, `slotFor(save, id)`, `activateSlot(save, id)`, `saveRun(save, run)`처럼 작고 타입 안전한 접근 함수를 두어 화면·엔진·오디오·PWA 코드가 저장 구조를 각자 임의로 해석하지 않게 한다. 게임 판정 함수는 가능한 한 계속 `Run`을 입력받아 다중 슬롯 때문에 전투 엔진을 불필요하게 변경하지 않는다.

2. 기존 저장 자동 이전

새 내부 저장 schema version과 key를 명확히 올린다. 예를 들어 `file-island-echoes:v3`를 사용하고 로드 우선순위는 v3 → v2 → v1로 한다.

- 기존 v2의 유효한 `run`은 해당 `run.characterId` 슬롯 하나로 그대로 이전
- 기존 v1은 현재의 안전한 v1→v2 변환을 거쳐 신태일 슬롯으로 이전
- 단일 저장의 화면, 전투 hand/draw/discard, 적 체력·턴·대상, 진화, 덱, story flag, 난수 seed와 시작 시각을 보존
- 공용 archive, clears, endings, settings와 오디오 설정을 보존
- 이전 후 해당 캐릭터를 `activeCharacterId` 또는 마지막 플레이 대상으로 설정
- 이전할 탐험이 없으면 빈 슬롯 컬렉션으로 시작

이전은 멱등적이어야 한다. 새 v3 쓰기가 성공하기 전에 v2/v1 원본을 삭제하지 않고, 쓰기 실패 시 다음 실행에서 원본으로 다시 복구할 수 있어야 한다. v3가 정상 저장된 뒤에는 오래된 key가 탐험을 되살리지 않게 우선순위와 정리 정책을 문서화한다.

v3에서 슬롯 하나만 손상됐다면 나머지 유효 슬롯, 도감과 설정까지 모두 버리지 않는다. 손상 슬롯만 제외하고 어느 캐릭터의 탐험을 복구하지 못했는지 사용자에게 알린다. 반대로 key/characterId 불일치, 중복 key, 8개 초과, 비정상 timestamp와 prototype pollution 입력을 안전하게 거부·정규화한다.

3. 타이틀의 캐릭터별 이어하기

타이틀 화면에서 저장된 탐험을 캐릭터별로 확인하고 직접 선택할 수 있게 한다.

저장 슬롯이 하나 이상이면 `이어할 탐험` 영역을 제공한다. 각 슬롯은 최소한 다음을 표시한다.
- 선택받은 아이와 파트너 이름 또는 기존 작은 초상
- 현재 챕터와 장소/진행 위치
- 현재 파트너 진화 형태
- 탐험 중, 전투 중, 보상 선택 중, 결과 확인 등 이해 가능한 현재 상태
- 마지막 저장 시각은 필요할 때만 짧게 표시
- 해당 캐릭터의 `이어하기` 버튼

모든 슬롯을 첫 화면에 큰 카드로 길게 늘어놓지 않는다. 8개가 있어도 모바일 세로 공간을 과도하게 차지하지 않는 compact list, 가로 스크롤 카드 또는 펼침 영역을 선택한다. 다만 캐릭터와 버튼을 혼동하지 않고 키보드·스크린리더로 각 슬롯을 구분할 수 있어야 한다.

기존 대표 `이어서 탐험` 버튼을 유지한다면 가장 최근에 저장한 슬롯을 명시적으로 이어 주고, 옆이나 아래에서 `다른 탐험 선택`으로 전체 슬롯을 열 수 있게 한다. 어떤 캐릭터를 여는지 표시하지 않은 채 임의 슬롯을 시작하지 않는다.

슬롯을 선택하면 해당 캐릭터를 활성화하고 그 Run의 현재 screen으로 들어간다. 전투 중 저장은 기존 카드 배분·애니메이션 복구 규칙을 따르고, 다른 캐릭터 슬롯로 전환했다가 돌아와도 카드를 다시 뽑거나 턴을 중복 진행하지 않는다.

4. 새 탐험과 캐릭터 전환

캐릭터 선택 카드와 상세 화면에도 해당 캐릭터의 저장 상태를 연결한다.

- 슬롯이 없는 캐릭터: 기존처럼 캐릭터·챕터를 골라 새 탐험 시작
- 진행 중 슬롯이 있는 캐릭터: `이어하기`를 우선 제공하고 `새로 시작`은 별도 보조 동작으로 제공
- 결과 화면 상태의 슬롯: `결과 보기` 또는 상태에 맞는 문구를 사용하고 `이어하기`라고 오해시키지 않음
- 다른 캐릭터로 새 탐험을 시작할 때 현재 캐릭터 탐험을 교체한다는 기존 경고를 표시하지 않음
- 같은 캐릭터로 새 탐험을 시작할 때만 그 캐릭터 슬롯이 교체된다는 확인 모달 표시
- 확인 모달에는 캐릭터 이름·챕터·현재 위치를 명시하고 다른 7명의 슬롯과 공용 도감·설정은 유지된다고 안내
- 취소하면 어떤 저장도 변경하지 않음

타이틀로 돌아가는 동작은 현재 슬롯을 먼저 정상 저장하고 게임 view만 전환한다. 다른 캐릭터로 바꾸는 과정에서 진행 중 모션을 억지로 직렬화하지 말고, 기존에 저장 가능한 안정 상태에서만 전환한다. 전투 중 홈 이동이 현재 허용된다면 저장된 전투 상태를 그대로 유지하고, 허용하지 않는 모션 구간에서는 버튼을 잠시 비활성화한다.

캐릭터별 슬롯은 챕터별 슬롯이 아니다. 한 캐릭터가 동시에 여러 챕터의 탐험을 보관하는 기능은 이번 범위에 넣지 않는다. 같은 캐릭터가 새 챕터로 출발하면 기존 해당 캐릭터 슬롯만 명시적 확인 후 교체한다.

5. 결과, 포기와 공용 기록

승리·패배·탐험 종료와 포기는 현재 활성 캐릭터의 슬롯에만 반영한다.

- 다른 캐릭터 슬롯의 Run 객체와 `updatedAt`을 변경하지 않음
- archive의 누적 탐험/승리, 캐릭터별 chapter clear와 ending은 기존처럼 한 번만 갱신
- 결과 화면을 다시 열거나 슬롯을 전환해도 완료 통계가 중복 증가하지 않음
- 결과 상태 슬롯은 새 탐험을 시작하기 전까지 결과를 다시 볼 수 있게 유지할 수 있음
- 같은 캐릭터로 새 탐험을 확정하면 기존 결과/진행 슬롯만 교체
- `모든 기록 초기화`는 8개 슬롯, 공용 archive와 settings를 기존 정의대로 초기화하되 명확한 전체 삭제 확인 유지

특정 캐릭터 슬롯만 지우는 기능이 UX에 꼭 필요하면 해당 슬롯 카드의 보조 메뉴에 넣고 캐릭터 이름을 포함한 별도 확인을 거친다. 이번 핵심 기능에 필요하지 않다면 임의로 삭제 기능을 확장하지 않는다.

6. 자동 저장과 원자성

기존 모든 persist 지점을 새 active slot 기반으로 전환한다.

- 카드 사용, 턴 종료, 이벤트 선택, 보상, 진화, 지도 이동과 설정 변경이 올바른 슬롯을 저장
- 설정만 변경해도 다른 슬롯의 `updatedAt`을 거짓으로 갱신하지 않음
- 진행 변경이 성공적으로 저장될 때만 해당 슬롯의 `updatedAt` 갱신
- localStorage 쓰기 한 번으로 모든 슬롯·archive·settings를 원자적으로 저장
- quota/write 실패 시 메모리만 앞서 전환해 저장된 슬롯과 UI가 어긋나지 않도록 기존 실패 정책 강화
- 탭 두 개에서 서로 다른 캐릭터를 플레이할 때 last-writer-wins로 슬롯 전체가 유실될 위험을 진단

다중 탭 완전 병합 기능까지 확장하지 않더라도 `storage` 이벤트나 revision 번호로 외부 변경을 감지해 경고하고, 오래된 탭이 다른 캐릭터 슬롯 전체를 조용히 덮어쓰지 않게 한다. 자동 병합을 구현한다면 같은 슬롯 충돌은 임의 병합하지 말고 최신 revision/명시적 선택으로 처리하며 archive 누적값을 중복 합산하지 않는다.

PWA 업데이트 적용 전 저장도 현재 active slot과 나머지 슬롯을 모두 보존해야 한다. standalone 앱과 같은 origin의 브라우저 탭에서 동일 저장을 공유한다는 v0.9 정책을 유지한다.

7. JSON 내보내기·불러오기

v0.7 데이터 관리 기능이 8개 슬롯을 모두 백업·복원하도록 갱신한다.

- 새 export payload에는 전체 `runs`, activeCharacterId, archive와 settings 포함
- 외부 파일 formatVersion은 내부 schema와 구분해 필요한 경우 명시적으로 올림
- v1/v2 원본 저장과 기존 formatVersion 1 export 파일을 계속 가져올 수 있음
- 이전 단일 run은 해당 캐릭터 슬롯에 배치
- 가져오기 미리보기에는 슬롯 수와 캐릭터별 챕터·진행 위치를 표시
- 손상 슬롯을 제외할 때 캐릭터별 경고를 표시하고 유효 슬롯은 보존
- 현재처럼 가져오기는 전체 데이터 교체이며, 요청하지 않은 슬롯 병합 UI를 임의로 추가하지 않음
- 교체 확인에는 현재 8개 슬롯과 공용 기록·설정 전체가 파일 내용으로 바뀐다고 정확히 안내
- 내보낸 뒤 다시 불러오면 모든 슬롯의 Run, updatedAt과 activeCharacterId가 동일하게 round-trip

8개의 긴 전투 로그로 기존 1MB 파일 한도를 넘을 수 있는지 실제 최악 크기를 계산한다. 필요하면 합리적인 상한으로 올리되 전체 바이트, 깊이, node 수, 슬롯 수, 배열과 문자열 길이 제한을 계속 적용해 과도한 입력을 막는다. 단순히 파일 크기 제한을 없애지 않는다.

8. UI 문구와 접근성

기존의 `새 캐릭터와 챕터를 확정하면 현재 탐험이 교체됩니다` 같은 단일 슬롯 전제 문구를 모두 찾아 바꾼다. 다른 캐릭터 시작에는 교체 경고가 없어야 하고, 같은 캐릭터를 덮어쓸 때만 정확한 경고가 나타나야 한다.

슬롯 목록과 버튼에는 캐릭터명, 파트너, 진행 상태를 포함한 접근 가능한 이름을 제공한다. 현재 활성 슬롯, 최근 슬롯과 선택 focus를 색만으로 구분하지 않는다. 모바일 최소 44×44px 터치 영역, 320px 폭, 200% 확대와 긴 한글 줄바꿈을 검증한다. 상단 고정바나 전투 화면에 저장 슬롯 설명 배너를 추가하지 않는다.

9. 검증

## 완료 조건

- 8명의 캐릭터가 각자 최대 하나의 독립된 탐험 슬롯을 가진다.
- 리키와 신나리를 번갈아 플레이해도 각자의 정확한 저장 위치와 전투 상태에서 이어진다.
- 다른 캐릭터의 새 탐험은 기존 슬롯을 삭제하지 않고, 같은 캐릭터의 새 탐험만 확인 후 교체한다.
- 기존 v1/v2 단일 저장이 해당 캐릭터 슬롯으로 안전하게 이전되고 공용 도감·설정이 유지된다.
- 자동 저장, 결과 통계, PWA 업데이트와 JSON 백업·복원이 모든 슬롯에서 일관된다.
- 슬롯 하나의 손상이나 저장 실패가 다른 슬롯과 공용 기록을 함께 잃게 하지 않는다.
- 모바일·키보드·스크린리더에서 각 슬롯과 현재 상태를 명확히 구분하고 선택할 수 있다.
