# v0.8.1 — 팝업과 전투 정보 배치 수정

- 상태: 완료
- 유형: 버그 수정
- 선행 버전: v0.8
- 제품 버전: `0.8.1`
- 작성일: 2026-09-11

## 증상

- 팝업의 X 닫기 영역이 왼쪽으로 길게 뻗어 제목이나 본문 글자를 가린다.
- 전투 중 에너지 표시 위에 내 디지몬 체력바가 한 번 더 표시되어 디지몬 아래 체력바와 중복된다.
- `능력 · 적 분석`이 전투 헤더가 아닌 문장 능력 영역에 있어 접근 위치와 정보 순서가 어색하다.
- 적마다 `선택한 대상`·`대상 선택` 텍스트 영역을 따로 두어 전투 UI의 세로 높이가 불필요하게 길고, 현재 대상 표시도 캐릭터와 시각적으로 떨어져 있다.

## 재현 절차

1. v0.8 게임을 데스크톱과 모바일 너비에서 연다.
2. 도움말, 설정, 도감, 능력·적 분석, 진화 확인 등 여러 팝업을 열고 우측 상단 X 주변의 제목과 본문을 확인한다.
3. 전투에 진입해 카드 영역 위와 내 디지몬 아래의 체력 표시를 비교한다.
4. 전투 제목, 문장 능력 영역과 턴 표시에서 `능력 · 적 분석`의 위치를 확인한다.
5. 적을 선택하고 대상 텍스트가 차지하는 높이, 적 스프라이트의 발밑과 현재 선택 상태를 확인한다.

## 기대 동작

- X 버튼의 시각 영역과 클릭·터치 영역이 우측 상단의 정사각형 안에만 있으며 팝업 글자를 가리지 않는다.
- 내 체력은 전투 화면의 디지몬 아래 체력바 한 곳에만 표시되고 에너지 위의 중복 체력바는 없다.
- 전투 헤더가 `전투 제목 → 능력 · 적 분석 → 턴 03` 순서로 읽힌다.
- 선택된 적 캐릭터의 발밑에 타깃 원이 표시되고 별도의 대상 텍스트 행은 제거되어 전투 UI 높이가 줄어든다.

## 다른 세션에 전달할 프롬프트

```text
현재 저장소의 File Island Echoes v0.8에서 발견된 팝업과 전투 정보 배치 문제를 v0.8.1 patch로 수정해줘.

먼저 AGENTS.md, docs/version-prompts/README.md, docs/version-prompts/v0.8-combat-ui.md, docs/v0.8-validation.md, 현재 dialog·battle heading·fighter·combat anchor 구현과 Git 상태를 확인한다. v0.8 구현 기준 ac9a3ce 이후 상태에서 작업하고 기존 사용자 변경사항을 보존한다.

이번 patch는 카드 효과, 적 AI, 체력 계산, 대상 선택 규칙, 문장 능력과 저장 데이터의 의미를 바꾸지 않는다. 이미 존재하는 정보를 요청한 위치로 옮기고 중복 표시와 겹침을 제거하는 범위다.

1. 팝업 X 닫기 영역 수정

도움말, 설정, 도감, 저장 관리, 능력·적 분석, 진화 확인, 귀환 확인과 새 탐험 확인을 포함해 공통 dialog의 우측 상단 X를 확인한다. 현재 `.dialog-top` 또는 닫기 버튼의 박스가 팝업 왼쪽으로 길게 늘어나 제목·본문 위를 덮거나 클릭을 가로채는 문제를 재현한다.

다음 조건으로 수정한다.
- X의 보이는 박스와 실제 pointer hit area는 우측 상단의 약 44×44px 정사각형 범위로 제한
- 닫기 버튼의 부모가 전체 너비를 차지하더라도 버튼 밖의 투명·배경 영역이 제목이나 본문의 클릭·선택을 가로채지 않음
- 팝업 제목과 첫 줄이 X 또는 sticky 배경 아래로 들어가지 않도록 우측 여백이나 전용 헤더 행 확보
- 긴 제목, 두 줄 제목과 200% 확대에서도 글자 가림 없음
- 스크롤되는 긴 팝업에서는 X가 찾기 쉬운 위치에 유지되되 본문을 덮는 넓은 막으로 만들지 않음
- X 아이콘은 버튼 중앙에 있고 시각적 박스와 실제 터치 영역이 어긋나지 않음
- `aria-label="닫기"`, Escape 닫기, 초기 포커스, focus-visible과 모달 포커스 복귀 유지

구현은 우측 상단 absolute/sticky 정사각 버튼과 제목의 padding-inline-end를 조합하거나, 너비가 명확한 dialog header 행을 사용하는 식으로 정리한다. 음수 margin과 전체 폭의 불투명 sticky 배경을 그대로 둔 채 z-index만 올리거나 내리는 임시 처방으로 끝내지 않는다.

2. 에너지 위의 중복 내 체력바 제거

전투 렌더링에서 `.combat-anchor` 안에 에너지/손패 도구막대 바로 위로 표시되는 compact 내 디지몬 체력바를 제거한다. 현재 구현의 `partnerHealth(r, true)`에 해당하는 중복 표시가 대상이다.

내 디지몬 스프라이트 바로 아래에 있는 기본 체력바 `partnerHealth(r)`는 유지한다. 상단 상태 또는 전투 화면의 다른 체력 표시까지 무조건 삭제하지 말고, 사용자가 지적한 **에너지 위의 중복 체력바만** 제거한다. 체력 상태의 단일 원천, 피해·회복 피드백과 접근 가능한 meter는 디지몬 아래 체력바에서 계속 동작해야 한다.

중복 체력바를 제거한 뒤 `.combat-anchor`, 모션 상태 문구와 `.hand-toolbar` 사이에 불필요한 빈 공간, margin 또는 깨진 정렬이 남지 않게 한다. 카드 사용, 적 행동과 체력 변화 애니메이션이 제거된 DOM을 계속 참조해 오류를 내지 않는지 확인한다.

3. `능력 · 적 분석`을 전투 헤더로 이동

현재 `crestHUD(r)`의 끝에 있는 `능력 · 적 분석` 버튼을 문장 능력 영역에서 제거하고 전투 헤더로 옮긴다. 같은 버튼을 두 곳에 중복 표시하지 않는다. 클릭 시 기존과 동일한 능력·적 분석 팝업을 열고 캐릭터별 문장 능력, 발동 조건과 적 상세 정보는 그대로 유지한다.

전투 헤더의 시각적·DOM 읽기 순서는 다음과 같아야 한다.

`전투 제목  →  능력 · 적 분석  →  턴 03`

- 왼쪽에 지역 eyebrow와 전투 제목
- 제목 오른쪽 또는 그 다음 열에 `능력 · 적 분석`
- 그 오른쪽에 현재 턴 `턴 03`

기존 `전투 안내` 버튼이 있다면 도움말 접근성을 잃지 않게 유지하되 위 세 항목의 순서를 깨거나 `능력 · 적 분석`과 혼동되지 않게 배치한다. 필요하면 전투 안내를 보조 아이콘 버튼으로 두거나 헤더의 후순위 컨트롤로 정리한다.

1280×900에서는 한 줄을 기본으로 한다. 390×844, 갤럭시 S23+ 실제 CSS viewport와 320×740에서는 제목을 말줄임하거나 헤더 내부 간격·라벨을 반응형으로 조정할 수 있지만, `능력 · 적 분석`과 `턴 03`을 숨기지 않는다. 두 컨트롤이 겹치거나 화면 밖으로 나가지 않고 터치 영역이 서로 침범하지 않아야 한다. 접근 가능한 DOM 순서도 제목 → 분석 → 턴을 따른다.

4. 선택 대상을 적 캐릭터 발밑의 원으로 표시

이전 요구사항처럼 `선택한 대상` 문구를 다음 행동 위의 별도 행으로 옮기지 않는다. 전투 UI의 세로 높이를 줄이기 위해 현재 스프라이트와 체력 아래에 있는 `.target-label` 및 선택 전용 텍스트 슬롯을 시각적으로 제거하고, 선택된 적 캐릭터의 **발밑**에 타깃 원을 그려 표시한다.

타깃 원 요구사항:
- 적 스프라이트가 서 있는 `.fighter-base` 주변 또는 바로 아래에 원형·타원형 링으로 표시
- 그림자와 구분되는 밝은 외곽선, 이중 링, 짧은 표식 등 형태 차이를 사용해 색만으로 선택 상태를 전달하지 않음
- 선택된 살아 있는 적 한 명에게만 표시
- 적을 바꾸면 기존 원은 즉시 사라지고 새 대상의 발밑으로 이동
- 스프라이트의 발, 체력바, 상태 아이콘과 다음 행동 예고를 가리지 않음
- 타깃 원을 위해 별도의 세로 공간을 추가하지 않고 기존 fighter base 영역 안에서 표현
- 선택 전후 적 스프라이트와 전장의 높이·위치가 움직이지 않음
- 공격·피격·적 행동 애니메이션 중에도 선택 대상을 알아볼 수 있고 효과가 끝나면 정상 상태로 복귀
- `prefers-reduced-motion`에서는 맥박 애니메이션 없이 고정된 선명한 원으로 표시

기존 `선택한 대상`, `대상 선택` 텍스트는 화면에 상시 노출하지 않는다. `전투 불능`처럼 별도의 의미가 필요한 상태는 기존 disabled·투명도·흑백 처리와 접근 가능한 이름으로 전달하되 빈 텍스트 행을 남기지 않는다. 대상 버튼에는 현재 선택 여부를 `aria-pressed="true/false"` 또는 동등한 접근성 상태로 제공하고, 접근 가능한 이름에는 선택 상태와 적 이름이 분명히 전달되게 한다. 키보드 focus-visible은 선택 원과 구별되는 별도 스타일을 유지한다.

다수 적, 단일 적, 크기가 큰 보스와 작은 적 모두에서 원이 각 캐릭터의 실제 발밑 중심에 맞아야 한다. 고정 픽셀 좌표를 적마다 임의로 하드코딩하기보다 fighter/sprite 컨테이너를 기준으로 정렬하고, 특별한 스프라이트에만 필요한 보정은 중앙 데이터나 명시적인 클래스에서 관리한다. 대상 버튼 전체의 클릭 기능과 카드 대상 판정은 그대로 유지한다.

중복 체력바와 대상 텍스트 행을 제거한 결과 전장부터 카드 손패까지의 세로 길이가 실제로 줄어들어야 한다. 제거된 요소 자리에 min-height, padding 또는 margin이 남아 공간을 계속 차지하지 않는지 확인한다.

5. 검증

팝업:
- 도움말, 설정, 도감, 저장, 능력·적 분석, 진화, 귀환과 새 탐험 팝업에서 X 박스 확인
- 제목이 짧거나 길 때, 팝업을 맨 위·중간까지 스크롤했을 때 글자 가림과 pointer 가로채기 확인
- 1280×900, 390×844, 갤럭시 S23+ 실제 CSS viewport, 320×740과 200% 확대
- X 터치, 키보드 Enter/Space, Escape, focus-visible과 닫은 뒤 포커스 복귀

전투:
- 에너지 위 compact 체력바가 사라지고 디지몬 아래 체력바가 남아 있는지 확인
- 피해, 회복, 진화와 최대 체력 변경 시 남은 체력바의 현재/최대값 및 위험 표시 확인
- 전투 제목 → 능력·적 분석 → 턴 번호의 시각적·DOM 순서 확인
- 분석 버튼이 한 번만 표시되고 기존 팝업 내용과 기능이 그대로 열리는지 확인
- 선택된 적 한 명의 발밑에만 타깃 원이 있고 `선택한 대상`·`대상 선택` 텍스트 행이 남지 않았는지 확인
- 대상 선택 전환을 반복해도 적과 전장의 높이가 변하지 않고 타깃 원만 이동하며 카드가 올바른 적에게 적용되는지 확인
- 마우스, 터치와 키보드 선택에서 `aria-pressed`, 접근 가능한 이름과 focus-visible 확인
- 공격·피격·적 행동 및 reduced-motion 상태에서 타깃 원의 위치와 가시성 확인
- 중복 체력바와 대상 텍스트 제거 전후의 모바일 전투 세로 높이를 비교하고 불필요한 빈 공간이 줄었는지 확인
- 단일 적, 적 2명 이상, 보스와 전투 불능 적 확인

회귀:
- 카드 배분·flip, 카드 사용·fade, 턴 종료와 적 행동 애니메이션
- 체력 계산, 대상 선택, 문장 능력 사용과 적 분석 내용
- reduced-motion, 모바일 터치, 상단 고정바와 dialog z-index
- npm test
- npm run build
- npm run check:pages

수정한 dialog 구조, 전투 헤더와 적 정보 DOM 순서를 자동 테스트로 고정한다. 가능하면 X 버튼의 bounding box가 과도하게 넓지 않고 제목 영역과 겹치지 않는 레이아웃 검증도 추가한다. 실제 모바일 브라우저에서 핵심 경로를 확인하고 결과를 docs/v0.8.1-validation.md에 기록한다.

package.json과 사용자에게 표시되는 버전을 0.8.1로 맞춘다. 저장 구조는 바뀌지 않으므로 저장 schema version은 올리지 않는다. README.md와 필요한 UI 문서를 갱신하고 docs/version-prompts/v0.8.1-combat-layout-fixes.md의 상태를 완료로 바꾼 뒤 구현 기준 커밋과 검증 결과를 기록한다. v0.8.1이 완료되기 전에는 후속 기능 버전을 시작하지 않는다.
```

## 완료 조건

- 모든 팝업의 X 닫기 영역이 우측 상단 정사각형 범위에 있고 글자나 조작을 가리지 않는다.
- 에너지 위 중복 체력바가 제거되고 내 디지몬 아래 체력바는 정상 동작한다.
- 전투 헤더가 `전투 제목 → 능력 · 적 분석 → 턴 03` 순서로 표시된다.
- 선택된 적의 발밑에 타깃 원이 표시되고 대상 텍스트 행은 제거되며, 선택 전환 시 전투 UI 높이나 캐릭터 위치가 변하지 않는다.
- 모바일, 접근성, 카드·적 행동 애니메이션과 기존 전투 판정이 회귀하지 않는다.

## 구현 기록
