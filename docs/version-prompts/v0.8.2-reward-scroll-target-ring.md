# v0.8.2 — 보상 카드·대상 링과 전투 HUD 정리

- 상태: 예정
- 유형: 버그 수정
- 선행 버전: v0.8.1
- 제품 버전: `0.8.2`
- 작성일: 2026-09-11

## 증상

- 좁은 화면의 전투 승리 보상 페이지에서 카드 3장이 한 줄 가로 스크롤로 유지되지 않고 다음 줄로 내려간다. 아래로 내려간 카드는 컨테이너 폭만큼 늘어나 카드 크기와 전체 레이아웃이 깨진다.
- v0.8.1의 선택 대상 발밑 링은 얇은 테두리 위주여서 전장과 잘 구분되지 않고, 선택된 캐릭터를 감싸는 시각적 초점이 부족하다.
- 첫 턴마다 `① 적을 눌러 대상 선택 → ② 카드를 눌러 바로 사용 → ③ 턴 종료. 적 머리 위의 예고를 먼저 확인하세요.`라는 긴 안내 배너가 전투 UI의 높이를 늘리고 이미 도움말에서 제공하는 내용을 반복한다.
- 문장 능력 영역이 `신태일 · 용기`, 긴 발동 조건, `중첩 없음`과 큰 능력 버튼을 여러 줄로 표시해 전투 화면의 세로 공간을 과도하게 차지한다.

## 참고 이미지 사용 범위

- 첫 번째 첨부 이미지는 좁은 보상 화면에서 카드 두 장 뒤의 세 번째 카드가 다음 줄로 내려가 가로로 늘어난 **오류 상태**를 확인하는 용도로만 사용한다.
- 두 번째 첨부 이미지는 선택된 캐릭터 발밑의 청록색 타원형 빛과 캐릭터 뒤로 은은하게 올라오는 반투명 선택 영역만 참고한다.
- 두 번째 이미지의 캐릭터, 배경, 체력·방어·상태 UI, 글꼴과 전체 화면 구도는 구현 참고 대상이 아니다. 첨부 이미지를 저장소에 복사하거나 게임 에셋으로 사용하지 않는다.

## 기대 동작

- 좁은 보상 화면에서도 카드 3장은 같은 폭을 가진 한 줄로 유지되고 손가락으로 좌우 스크롤해 선택한다.
- 선택된 적의 발밑에는 청록색의 반투명 타원형 링과 은은한 수직 빛 영역이 표시되며 캐릭터·정보·레이아웃을 가리지 않는다.
- 첫 턴 조작 안내 배너가 제거되고 이후 전투 UI 패치에서도 요청하지 않은 상시 설명 문구를 덧붙이지 않는다.
- 문장 능력은 한 줄 중심의 compact HUD로 줄이고, 실제 고유 중첩은 내 디지몬의 방어 표시 위에서 확인한다.

## 다른 세션에 전달할 프롬프트

```text
현재 저장소의 File Island Echoes v0.8.1에서 발견된 보상 카드 레이아웃과 대상 선택 링 디자인 문제를 v0.8.2 patch로 수정해줘.

먼저 AGENTS.md, docs/version-prompts/README.md, docs/version-prompts/v0.8-combat-ui.md, docs/version-prompts/v0.8.1-combat-layout-fixes.md, docs/v0.8.1-validation.md, reward screen·card·fighter base 관련 HTML/CSS와 Git 상태를 확인한다. v0.8.1 구현 기준 81b4e49 이후 상태에서 작업하고 기존 사용자 변경사항을 보존한다.

이번 patch는 보상 카드의 내용과 선택 결과, 덱 추가 규칙, 적 대상 판정, 카드 효과, 전투 수치와 저장 데이터의 의미를 변경하지 않는다. 반응형 레이아웃과 대상 선택의 시각 표현만 수정한다.

1. 좁은 전투 승리 보상 화면을 한 줄 가로 스크롤로 수정

전투 승리 후 `어떤 기술을 기억할까?` 화면에서 보상 카드 3장이 좁은 viewport에 들어가지 않을 때 현재는 두 장이 첫 줄에 놓이고 세 번째 카드가 다음 줄의 전체 폭으로 늘어난다. 첨부된 첫 번째 화면처럼 세로로 wrap되는 것이 오류 상태다.

현재 CSS cascade를 확인한다. `style.css`의 모바일 `.reward-cards`에는 가로 overflow와 scroll snap이 설정되어 있지만, 뒤에 로드되는 `combat.css`의 `@media(max-width:760px)`에서 `.reward-cards { flex-wrap: wrap; ... }`가 이를 덮어쓰는 구조가 있다면 그 충돌을 제거하거나 한 곳의 명확한 반응형 규칙으로 통합한다. 단순히 더 높은 specificity를 계속 쌓지 않는다.

좁은 화면 요구사항:
- `.reward-cards`는 `display:flex` 한 줄을 유지하고 `flex-wrap: nowrap`
- 컨테이너 안에서만 `overflow-x: auto`, 세로 overflow는 불필요하게 만들지 않음
- 각 보상 카드는 `flex: 0 0 <card-width>`에 준하는 고정 기준 폭을 사용해 줄어들거나 전체 행 너비로 늘어나지 않음
- 세 카드의 폭과 기본 높이, 테두리와 내부 정보 배치가 일관됨
- 첫 카드와 마지막 카드가 화면 가장자리에서 잘리지 않도록 inline padding과 scroll padding 확보
- 손가락 드래그, 트랙패드와 마우스 휠/Shift+휠 환경에서 접근 가능
- 적절한 `scroll-snap-type: x proximity` 또는 동등한 방식으로 카드가 읽기 좋은 위치에 멈춤
- 키보드 Tab으로 화면 밖 카드에 포커스하면 해당 카드가 자동으로 보이는 영역에 들어옴
- 보상 카드 컨테이너 때문에 전체 문서에 가로 스크롤이 생기지 않음
- `카드를 받지 않고 계속` 버튼은 카드 스크롤 영역 밖의 아래쪽에 그대로 보임

320×740, 360px, 390×844, 갤럭시 S23+ 실제 CSS viewport와 첨부 화면과 비슷한 약 600px 폭에서 카드가 절대로 다음 줄로 내려가지 않는지 확인한다. 다음 카드가 있다는 사실을 알 수 있도록 오른쪽 카드의 일부가 살짝 보이거나, 과하지 않은 스크롤 힌트·그라데이션을 제공할 수 있다. 힌트가 카드 선택을 가리거나 필수 조작이 되어서는 안 된다.

데스크톱처럼 세 카드가 충분히 들어가는 폭에서는 세 장을 중앙 정렬해 한눈에 볼 수 있다. 데스크톱 규칙까지 무조건 왼쪽 정렬하거나 불필요한 스크롤바를 만들지 않는다. 카드 설명 길이가 서로 달라도 세 번째 카드만 다른 폭이 되거나 내부 버튼·텍스트가 잘리지 않게 한다.

2. 대상 선택 발밑 링 디자인 개선

v0.8.1에서 `.enemy.targeted .fighter-base:after`로 만든 노란색 이중 테두리 링을 개선한다. 사용자가 제공한 두 번째 참고 이미지에서는 선택된 캐릭터 발밑에 넓은 청록색 반투명 타원이 있고, 그 타원에서 캐릭터 뒤쪽으로 부드러운 수직 빛 영역이 올라와 선택된 대상을 한 덩어리로 보여 준다. **이 선택 표현만** 참고하고 이미지의 다른 UI나 캐릭터·배경은 따라 하지 않는다.

목표 디자인:
- 적 발밑 중심에 스프라이트 너비와 어울리는 넓고 낮은 청록·시안 타원
- 타원 내부의 옅은 반투명 채움, 조금 더 밝은 외곽선과 부드러운 바깥 glow
- 바닥 타원에서 스프라이트 높이의 약 70~100%까지 올라오는 은은한 수직 선택광
- 수직광은 아래가 조금 선명하고 위로 갈수록 투명해지는 gradient
- 수직광의 좌우 경계는 딱딱한 직사각형처럼 보이지 않도록 부드럽게 fade
- 전체 효과는 배경보다 앞, 적 스프라이트보다 뒤에 배치
- 적의 다음 행동, 방어·상태, 이름과 체력바보다 뒤에 있어 정보를 가리지 않음
- 현재의 노란색 단선 링이나 마법진처럼 복잡한 문양보다 디지털 스캔·선택 필드에 가까운 절제된 표현

CSS pseudo-element, gradient와 box-shadow 등 가벼운 방식으로 구현하고 참고 이미지를 잘라 배경 이미지로 사용하지 않는다. 필요하면 fighter base의 `::before`는 기존 그림자로, `::after`는 청록색 발밑 타원으로 사용하고, 별도 장식 요소나 fighter의 pseudo-element로 수직광을 만든다. z-index와 stacking context를 명시적으로 정리해 수직광이 스프라이트 위를 뿌옇게 덮거나 전장 배경 뒤로 사라지지 않게 한다.

표현 조건:
- 살아 있는 선택 대상 한 명에게만 표시
- 대상을 바꾸면 이전 효과는 즉시 사라지고 새 적에게 표시
- 선택 전후 fighter의 크기, 위치와 전투 UI 높이는 변하지 않음
- 단일 적, 적 2명 이상과 큰 보스에서도 각 스프라이트 발밑에 맞는 크기
- 작은 적에서 링이 지나치게 크거나 큰 적에서 발 안쪽에 묻히지 않도록 `clamp()`, 백분율 또는 중앙화된 스프라이트 보정 사용
- 어두운 숲, 밝은 설원 등 모든 전투 배경에서 식별 가능하되 캐릭터보다 밝게 타지 않음
- 공격·피격·적 행동 애니메이션과 함께 재생될 때 원래 위치에서 어색한 잔상이 남지 않음
- `prefers-reduced-motion`과 게임의 움직임 줄이기에서는 고정 타원과 고정 수직광 사용
- 일반 모션에서는 opacity와 scale을 아주 약하게 숨 쉬게 할 수 있지만 빠른 깜빡임이나 큰 확대·축소는 사용하지 않음

대상 선택은 시각 효과만으로 접근성 정보를 대체하지 않는다. v0.8.1의 `aria-pressed`, 선택 상태가 포함된 접근 가능한 이름과 focus-visible을 유지한다. focus-visible은 청록색 선택 필드와 구분되는 키보드 전용 윤곽이어야 한다. `선택한 대상`·`대상 선택` 텍스트 행을 다시 추가하지 않는다.

3. 첫 턴 조작 안내 문구 제거

전투 첫 턴에 다음 문구를 표시하는 `.guide-banner`를 렌더링하지 않도록 제거한다.

`① 적을 눌러 대상 선택 → ② 카드를 눌러 바로 사용 → ③ 턴 종료. 적 머리 위의 예고를 먼저 확인하세요.`

`save.settings.guide && b.turn===1` 조건과 해당 배너 마크업을 제거하고, `.guide-banner` 스타일이 더 이상 다른 곳에서 사용되지 않는다면 함께 정리한다. 같은 문구나 축약한 변형을 전투 헤더, 전장, 카드 영역 또는 toast로 옮기지 않는다. 조작 방법은 기존 도움말의 `게임 방법` 챕터에서 확인할 수 있으면 충분하다.

설정 화면의 `첫 턴 안내` 토글이 이 배너만 제어한다면 사용자에게 아무 효과가 없는 설정으로 남기지 말고 설정 UI와 action handler를 함께 정리한다. 기존 v0.8.1 저장 및 JSON 백업에 `guide` 값이 들어 있어도 불러오기가 실패하지 않게 이전 데이터는 안전하게 허용·무시한다. 이 정리만으로 저장 schema version을 올리지 않는다.

앞으로 전투 UI를 수정할 때 사용자가 명시적으로 요청하지 않은 다음 요소를 임의로 추가하지 않는다.
- 상시 노출 튜토리얼 문장
- 매 전투 또는 매 턴 반복되는 조작 순서 배너
- 화면 공간을 차지하는 설명 카드와 홍보성 문구
- 이미 도움말에 있는 내용을 반복하는 안내

현재 체력, 에너지, 적 행동 예고, 상태 효과, 오류·확인 메시지와 접근 가능한 이름처럼 플레이 판단이나 조작에 필요한 정보는 제거 대상이 아니다. 새로운 설명이 꼭 필요하다면 전투 화면에 상시 배치하지 말고 도움말에 통합하거나 사용자가 직접 요청한 최소한의 맥락 안내로 제한한다.

4. 문장 능력 HUD를 단순화하고 고유 중첩을 방어 위로 이동

현재 `.crest-hud`는 캐릭터 이름·문장, 긴 발동 조건, 고유 중첩 문장과 큰 능력 버튼을 별도 영역에 배치한다. 예를 들어 신태일은 다음 세 줄과 큰 버튼으로 표시된다.

`신태일 · 용기`

`이번 전투에서 공격 카드 2장 사용`

`중첩 없음`

활성 캐릭터는 전투 화면에서 이미 알 수 있으므로 이름을 반복하지 않고, 빈 상태를 설명하는 `중첩 없음` 행은 완전히 제거한다. 문장 영역은 다음 정보만 가진 한 줄 중심의 compact action bar로 바꾼다.

- 문장 아이콘
- `용기 · 용기의 결단`처럼 문장명과 고유 능력명
- `공격 0/2`, `사용 가능`, `사용 완료` 또는 `봉인 2턴`처럼 짧고 현재 상태에 맞는 진행 표시
- `사용` 버튼

신태일 예시:

`[용기 아이콘] 용기 · 용기의 결단   공격 0/2   [사용]`

버튼 안에 긴 능력명을 다시 반복하지 않는다. 능력명은 왼쪽에 표시하고 버튼의 보이는 라벨은 `사용`으로 줄이되, 접근 가능한 이름은 `용기의 결단 사용`처럼 전체 의미를 제공한다. 사용할 수 없으면 기존처럼 disabled 상태를 유지하고 그 이유 또는 진행 상태를 읽을 수 있게 연결한다.

발동 진행은 실제 전투 상태에서 계산한다. 추측으로 숫자를 만들지 말고 기존 `AbilityState`와 `crestReady` 조건을 사용한다. 고유 중첩 값 자체는 아래의 디지몬 상태 칩에서 한 번만 보여 주고 문장 HUD에 같은 숫자를 중복하지 않는다.
- 신태일: `공격 n/2`
- 매튜: `연계 2 필요` 또는 `사용 가능`과 손패 조건
- 한소라: 방어 8 또는 체력 70% 이하 조건을 짧게 표시
- 장한솔: 턴, 지원 카드 사용과 뽑기 더미 조건 중 아직 충족되지 않은 핵심 조건
- 이미나: `개화 2 필요`, 해로운 효과 또는 `사용 가능`
- 정석: `비축 2 필요` 또는 `사용 가능`
- 리키: `희망 2 필요` 또는 `사용 가능`
- 신나리: `빛 2 필요`, 오염 조건 또는 `사용 가능`

긴 조건 전체는 능력·적 분석 팝업과 도움말에 그대로 남기고 전투 HUD에서는 현재 진행을 짧게 보여 준다. 조건을 축약해 실제 판정과 다른 의미가 되지 않게 한다.

문장 HUD에 있던 캐릭터 고유 중첩은 내 디지몬 쪽 전투 상태로 이동한다. 다음 자원은 해당 캐릭터를 플레이할 때 디지몬 위의 방어 표시보다 한 단계 위에 작은 상태 칩으로 표시한다.
- 매튜: 연계
- 이미나: 개화
- 정석: 비축
- 리키: 희망
- 신나리: 빛

고유 중첩 칩은 현재값과 실제 최대값을 `연계 0/4`, `개화 0/6`, `비축 0/3`, `희망 0/3`, `빛 0/6`처럼 표시한다. 값이 0이어도 해당 캐릭터의 핵심 자원을 알 수 있도록 칩은 유지하되 `중첩 없음`이라는 별도 문장이나 빈 행은 만들지 않는다.

재생·반격·화상·약화처럼 일반 전투 효과는 고유 중첩으로 오인되지 않도록 기존 상태 효과 영역에서 관리한다. 신태일의 공격 카드 사용 수와 장한솔의 지원 카드 사용 수는 소모형 중첩이 아니라 문장 발동 진행이므로 compact 문장 HUD에 표시한다. 한소라는 별도 고유 중첩이 없으므로 빈 칩이나 `중첩 없음`을 만들지 않는다.

고유 중첩과 방어 표시는 다음 순서를 가진다.

1) 고유 중첩 칩(해당 캐릭터에 있을 때)
2) 방어 수치
3) 내 디지몬 스프라이트

이 두 상태 행은 전장 안에서 스프라이트 위에 붙는 compact overlay 또는 동등한 고정 레이어로 구성해 중첩 값이 0에서 증가하거나 사라져도 fighter 높이와 전투 UI 전체 높이가 변하지 않게 한다. 캐릭터·적 행동·배경을 과도하게 가리지 않고, 모바일에서 적의 다음 행동 영역과 충돌하지 않아야 한다. 고유 중첩은 이름과 숫자를 함께 표시해 색만으로 구분하지 않는다.

compact 문장 HUD는 데스크톱에서 약 44~56px 높이의 한 줄을 목표로 한다. 320px 모바일에서 정말 필요한 경우 두 줄까지 허용하지만 캐릭터 이름, `중첩 없음`, 긴 조건 문장을 다시 넣어 높이를 늘리지 않는다. 능력 버튼은 최소 터치 영역을 유지하고 문장 아이콘·진행 상태·버튼이 겹치거나 가로 문서 overflow를 만들지 않게 한다.

5. 검증

보상 카드:
- 보상 카드 1장, 2장, 3장과 설명 길이가 서로 다른 카드 조합 확인
```

## 완료 조건

- 좁은 보상 화면의 모든 카드가 같은 폭의 한 줄을 유지하며 컨테이너 안에서 좌우 스크롤된다.
- 세 번째 카드가 다음 줄로 내려가거나 전체 폭으로 늘어나지 않는다.
- 선택된 적의 발밑에 청록색 반투명 타원·외곽광과 위로 부드럽게 사라지는 수직 선택광이 표시된다.
- 대상 효과가 정보와 캐릭터를 가리지 않고 선택 전환이나 전투 애니메이션 중 잘못된 적에게 남지 않는다.
- 대상 텍스트 행을 되살리거나 전투 UI 높이를 늘리지 않으며 접근성 상태를 유지한다.
- 첫 턴 조작 안내 배너와 효과 없는 설정 토글이 제거되고 기존 저장 데이터는 계속 불러올 수 있다.
- 전투 UI에 요청하지 않은 상시 설명이나 반복 튜토리얼 문구가 추가되지 않는다.
- 문장 능력 영역이 한 줄 중심의 compact HUD로 줄고 캐릭터 이름과 `중첩 없음`을 반복하지 않는다.
- 캐릭터 고유 중첩이 내 디지몬의 방어 표시 위에 있으며 값 변화가 전투 UI 높이를 바꾸지 않는다.
- 모바일·키보드·reduced-motion과 기존 보상·전투 판정이 회귀하지 않는다.
