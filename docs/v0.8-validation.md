# v0.8 구현·검증 기록

기준: v0.7.1, 커밋 `340c57c`. 게임 표시명과 저장 키·schema v2는 유지했다.

## 구현

- `src/card-ui.ts`와 `src/combat.css`: 세로 카드, 둥근 종이 프레임, 비용·기술·키워드·전용 단계, 타입별 SVG 기술 도형. 모바일 손패는 겹치지 않는 가로 스크롤로 표시한다. 효과 설명은 14px 기준이며 내용이 길면 카드 높이가 늘어난다.
- 사용자의 추가 지시에 따라 **카드를 한 번 누르면 바로 사용**한다. 재확인 영역은 없으며 대상은 적을 눌러 먼저 선택한다. 효과·비용은 앞면에 항상 표시하고 키보드 포커스와 눌림 상태를 제공한다.
- 뒷면은 별도 `public/assets/ui/card-back.svg`다. 남색, 대칭 회로, 원형 장치 문양을 직접 제작했다. 배분 460ms 중 70%의 옆면 시점에서 뒷면을 숨기고 앞면을 표시한다. 글자가 거꾸로 보이거나 두 면이 동시에 노출되지 않도록 면의 표시를 명시적으로 전환한다. 카드별 시작 간격은 75ms다.
- 사용 연출은 340ms, 상승 56px → 효과 표시 → 76px까지 이동하며 사라진다. overlay 복제본은 접근성 트리와 입력에서 제외한다. 원래 카드의 슬롯은 연출 동안 유지하고 가로 스크롤도 보존한다.
- `MotionQueue`: 카드/턴 판정은 한 번 확정·저장한 뒤 UI 스냅샷만 순서대로 표시한다. 입력 잠금은 타이머로 종료하며 animationend에 의존하지 않는다. 취소 시 타이머·복제본·임시 상태를 정리하고 확정된 결과로 돌아간다. 4초 watchdog도 둔다.
- 적 행동은 기존 `endTurn`에 선택적인 스냅샷 수집만 추가했다. 상태 피해 → 살아 있는 적 순서(각 350ms) → 결과 → 새 카드 배분이다. 다단 공격은 기존 합산 피해를 유지하고 타격 횟수만큼 펄스를 표시한다. 방어·강화·약화·화상·오염·흡수·봉인·소환 등은 해당 아이콘과 행동 이름을 표시한다.
- `prefers-reduced-motion`과 게임 설정 중 하나라도 켜면 이동/회전을 없앤다. 카드 50ms, 적 단계 40ms의 상태 전환으로 같은 결과를 표시한다. 탭 숨김/페이지 이탈/메뉴 진입은 연출을 정리한다.
- 파트너 아래 meter와 숫자를 추가했다. 모바일 손패 위에도 같은 Run에서 파생한 체력 바를 sticky로 제공한다. 위험 상태는 색 외에 “위험” 문구를 표시한다.
- 추가 사용자 지시에 따라 새 전투 진입과 전투 이어하기 시 고정 상단바 아래에 **지역 / 전투**와 제목이 오도록 스크롤한다. 일반 카드·턴 행동은 해당 위치로 되돌리지 않는다.
- 상단바는 sticky, 네 컨트롤은 한 줄 고정 열이다. 좁으면 왼쪽 제목 글자를 시각적으로 숨기고 버튼을 아이콘으로 축약한다. 44px 이상 터치 영역과 접근 가능한 이름은 유지한다.
- 기록은 저장의 최신 우선 문자열 배열을 유지하되 발생 번호를 문자열에 보존한다. 화면은 복사본을 역순으로 읽어 위→아래 시간순으로 표시한다. 최대 999건을 유지하고 오래된 항목이 빠져도 번호를 다시 매기지 않는다. 이전 버전의 최대 10건 저장은 남아 있는 항목부터 번호를 붙인다. 과거에 삭제된 기록은 복원하지 않는다.

## 검증 근거

- Vitest 91개: 기존 82개와 큐 취소·중복 완료·watchdog·기록 번호·적 순서/중간 사망 등 9개 추가.
- `node scripts/verify-combat-baseline.mjs`: 이전 엔진과 608개 시나리오, 8명, 최대 3턴의 카드 비용/효과·적 결과·난수·진화가 일치했다. 변경 대상으로 지정한 기록 표현과 시작 시각만 비교에서 제외한다.
- 로컬 `qa/combat-checks.ts`는 실제 DOM 버튼으로 8명 각각 첫 배분 → 카드 → 3턴을 진행한다. 연타 중 턴 중복 진입과 카드 중복 적용이 없고 파트너 체력 표시가 일치했다. 메뉴로 연출 취소, 상태 피해 사망, 카드 승리와 다중 적 순서도 확인했다.
- 적 행동 12종(공격, 방어, 약화, 비용 증가, 화상, 오염, 강화, 교란, 봉인, 저주, 흡수, 소환)에서 실제 모션 표시와 다음 턴 완료를 확인했다.
- 8명 각각 두 진화 단계, 보스 승리와 패배 화면/복귀를 확인했다. 완료 직전 상태는 합성 fixture이며 모든 캐릭터의 캠페인 전체를 사람이 수동 플레이한 것은 아니다.
- 카드 배분 중 실제 computed visibility를 샘플링해 뒷면→앞면과 동시 노출 없음 확인. 120ms/460ms의 정지 샘플도 브라우저에서 육안 확인했다.
- 기록의 과거 스크롤은 그대로 유지되고, 끝을 읽는 경우에만 새 항목으로 따라가는 DOM 검사 통과.

자동 검사와 모바일 크기 검증은 데스크톱 Chromium에서 수행했다. 실제 Galaxy S23+ / iOS Safari와 저사양 실기기는 연결되어 있지 않다. 탭 백그라운드 전환은 취소 경로로 처리하며 렌더링 성능·오디오 출력 지연의 실기기 수치는 측정하지 않았다.


## 최종 사용자 조정과 프로덕션 확인

- 전투 문장 영역의 키워드 버튼을 제거하고 상단 도움말을 유지했다. 대기 시 카드 사용 안내 문구를 제거했다.
- 살아 있는 적의 버튼이 연출 잠금으로 disabled가 되어도 opacity 1을 유지한다. 원인은 공통 button:disabled의 opacity .42였다. 실제 busy=true, disabled=true 상태에서 계산된 opacity 1 확인.
- 최종 일반 모드: 8명 한 번 터치 사용/3턴/중복 입력/체력 일치, 두 적 행동 순서, 승리/상태 사망/메뉴 취소 ALL PASS. 움직임 줄이기에서도 8명 및 전체 검사 통과. 짧은 단계의 검사 샘플 간격은 10ms로 보정했다.
- 1280×900 및 384×854 프로덕션 화면, 320×740 QA 화면에서 상단 단일 행, 44px 이상 버튼, 문서 가로 넘침 없음 확인. 384px에서 카드 앞면과 파트너 체력 표시를 육안 확인했다.
- 실제 새 탐험 → 신태일 → 챕터 → 이야기 → 지도 → 전투 → 카드 한 번 사용 → 턴 종료 → index.html 직접 접근/새로고침 → 이어하기. 턴 2와 체력이 복원되었으며 전투 제목 영역 top 71.6px, 상단 메뉴 bottom 60px 확인.
- 최종 JS 약 161.83kB (gzip 56.85kB), CSS 약 64.79kB (gzip 15.03kB). 초기 로딩은 기존 약 2.6MB 수준이며 새 카드 뒷면은 약 2KB. 전체 파일에는 지연 로딩되는 두 오디오 코덱까지 포함되어 약 22.7MB다.
- 공개 배포 전 로컬 프로덕션 HTTP 215 URL 모두 200, 빌드 해시와 프로젝트 기본 경로 확인.

- 320px / 문서 글자 200%에서 카드 설명 28px, 카드 clientHeight/scrollHeight 모두 518px로 내용 잘림 없음, 문서 가로 넘침 없음 확인. OS 글자 확대나 브라우저 전체 줌과는 별도 검사다.
